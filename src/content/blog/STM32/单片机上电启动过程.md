# STM32 的上电启动过程

> 从按下电源开关，到 `main()` 第一行代码执行，STM32 实际上已经完成了一整套启动流程。


![MCU STARTUP](/learning-os/image/STM32/stm32-startup.png)

## 1. main() 真的是程序的起点吗？

以一个最普通的 STM32 程序为例：

```c
int main(void)
{
    while (1)
    {
    }
}
```

我们平时写程序时，似乎程序天然就是从 `main()` 开始执行。

但 MCU 上电以后，CPU 并不知道：

* `main()` 在哪里；
* 栈在哪里；
* Flash 在哪里；
* RAM 是否需要初始化；
* 系统时钟是多少；
* 全局变量应该是什么值。

所以：

> `main()` 并不是 STM32 真正意义上的第一条指令。

在进入 `main()` 之前，还有一系列底层初始化工作需要完成。

---

## 2. STM32 上电以后发生了什么？

STM32 上电或者产生复位后，Cortex-M 内核首先进入 Reset 状态。

常见复位来源包括：

* Power-On Reset
* NRST 引脚复位
* Watchdog Reset
* Software Reset
* Brown-Out Reset

复位完成后，CPU 开始寻找程序入口。

这里首先涉及一个问题：

> STM32 到底从哪里启动？

---

## 3. Boot 模式：STM32 从哪里启动？

STM32 通常支持多种启动区域，例如在STM32F10xxx里,可以通过`BOOT[1:0]`引脚选择三种不同启动模式：


![启动模式](/learning-os/image/STM32/boot_mode_choose.png)

- 从Flash启动，将Flash地址0x08000000映射到0x00000000，这样启动以后就相当于从0x08000000开始的，这是我们最常用的模式
- 从SRAM启动，将SRAM地址0x20000000映射到0x00000000，这样启动以后就相当于从0x20000000开始的，用于调试；
- 从系统存储器启动，将系统存储器地址0x1FFFF000映射到0x00000000，这样启动以后就相当于从0x1FFFF000开始执行的，值得注意的是这个系统存储器里面存储的其实是STM32自带的Bootloader代码.

---

## 4. CPU 为什么不是直接跳到 main()？

以 Cortex-M 为例，程序 Flash 开头存放的并不是普通代码，而是：

> **中断向量表 Vector Table**

![上电后的向量表](/learning-os/image/STM32/Vector-Meter-After-Power-On.png)


向量表的前两个数据最重要：

前两段地址主要是用来指定SP和PC的初值，上一节我们已经知道了映射关系，所以这时已自动从0x08000000位置处读取数据赋值给了栈指针SP，从0x08000004位置处读取数据赋值给了PC。

因此可以简单理解为（可以查看`startup_stm32f103xb.s`汇编源文件或者`startup_stm32f103xb.lst`列表文件）：

```text
0x08000000 → 初始栈顶地址-Top of Stack
0x08000004 → Reset_Handler 地址
```


需要注意的是这个复位向量初始值并不是固定的，可以通过一个叫“向量表偏移量寄存器”来修改定位。

![向量表偏移量寄存器](/learning-os/image/STM32/向量表偏移量寄存器.png)

那__initial_sp在哪里？到底做了哪些事？

`startup_stm32f103xb.s`文件的开头
~~~
Stack_Size		EQU     0x400

                AREA    STACK, NOINIT, READWRITE, ALIGN=3
Stack_Mem       SPACE   Stack_Size
__initial_sp
~~~
Stack_Size EQU 0x00000400        这里定义了堆栈的大小为 0x00000400

AREA STACK, NOINIT, READWRITE, ALIGN=3
这行声明了一个名为 STACK 的内存区域：
NOINIT 表示该区域不需要初始化（即留空，不填充默认值）。
READWRITE 表示该区域可读可写，适合用作堆栈。
ALIGN=3 表示按 2^3（即 8 字节）对齐，以满足 STM32 CPU 的内存对齐要求。

Stack_Mem：
表示堆栈内存的起始地址（栈底）。
是堆栈的底部边界，程序运行时 SP 不会低于这个地址，否则会发生堆栈溢出。

__initial_sp：
这是一个标号，表示堆栈内存的结束地址（栈顶），程序启动时，CPU 会将这个地址加载到 SP 寄存器，作为堆栈的初始指针，随着数据压栈，SP 会从这个地址开始向下（地址减小）移动

## 5. Reset_Handler 到底干了什么

~~~
Reset_Handler    PROC
                 EXPORT  Reset_Handler             [WEAK]
     IMPORT  __main
     IMPORT  SystemInit
                 LDR     R0, =SystemInit
                 BLX     R0
                 LDR     R0, =__main
                 BX      R0
                 ENDP
~~~

执行 Reset_Handler → SystemInit() 配置时钟 →
跳转 __main → 初始化 C 运行时环境 →
进入 main() → 用户应用程序运行

`SystemInit`函数，也就是初始化系统时钟了。

`__main`	初始化 .data、清零 .bss、初始化 C/C++ Runtime、main()


![STM32 Flash 与 RAM 内存布局](/learning-os/image/STM32/STM32Flash与RAM内存布局.png)


编译 STM32 工程后，打开 `.map` 文件可以查看各段的具体地址和大小

##  一句话总结
可以把启动流程想象成“起床去上班”：

上电/复位：闹钟响了，你醒了。

设置堆栈__initial_sp：整理床铺，准备临时放东西的地方。

跳转 Reset_Handler：开始起床流程。

调用 SystemInit：洗漱、穿衣服（准备硬件）。

跳转 __main：吃早餐（准备软件环境）。

调用 main：出门上班（运行你的任务）
