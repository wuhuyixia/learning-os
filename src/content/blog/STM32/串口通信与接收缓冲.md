# 简单的串口收发

## 串口传输速度计算


| 组成部分 | 位数 |
|---------|------|
| 起始位   | 1    |
| 数据位   | 8    |
| 校验位   | 0    |
| 停止位   | 1    |
| **合计** | **10** |

> 每传 **1 字节数据（8 bit）**，实际发 **10 bit**（含 2 bit 开销）


```text
有效字节速率 = 波特率（每秒传输的 bit 数） ÷ 每帧总位数
             = 115200 ÷ 10
             = 11520 字节/秒
```

## 阻塞式串口通信（STM32 HAL 库）


```c
uint8_t rx_buffer[10];
HAL_UART_Receive(&huart1, rx_buffer, 10, HAL_MAX_DELAY);
HAL_UART_Transmit(&huart1, rx_buffer, 10, 0xff);
```

### 接收阶段
- 程序执行到 `HAL_UART_Receive()` 时**停止不动**
- 等待直到收到 10 字节数据后，才继续往下走
- 如果一直收不到数据，程序**永久卡死**在此处

### 发送阶段
- 程序执行到 `HAL_UART_Transmit()` 时**暂停**
- 等待直到 10 字节全部发送完毕
- 发送完成后继续执行下一条代码

## 中断式串口接收

```c
HAL_UART_Receive_IT(&g_uart1_handle, (uint8_t *)&rx_buffer, RXBUFFER_SIZE);
```


```
// UART_HandleTypeDef 内部相关成员
huart1.pRxBuffPtr   = rx_buffer;      // 缓冲区指针
huart1.RxXferSize   = 10;             // 期望总字节数
huart1.RxXferCount  = 10;             // 剩余待收字节数（递减）
huart1.RxState      = HAL_UART_STATE_BUSY_RX;  // 接收忙状态
```
```
void HAL_UART_IRQHandler(UART_HandleTypeDef *huart)
{
    // 判断是否是接收中断
    if (__HAL_UART_GET_FLAG(huart, UART_FLAG_RXNE) != RESET)
    {
        // 读取 1 字节存入缓冲区
        *huart->pRxBuffPtr++ = (uint8_t)(huart->Instance->DR & 0xFF);
        huart->RxXferCount--;   // 剩余计数减 1
        
        if (huart->RxXferCount == 0)  // 收满了
        {
            __HAL_UART_DISABLE_IT(huart, UART_IT_RXNE);  // 关闭中断
            
            // 调用用户的回调函数
            HAL_UART_RxCpltCallback(huart);
        }
    }
}
```


# DMA空闲中断与不定长度数据接受


有些传输协议会在传输数据前先定好传输的长度，这样可以认为是固定长度的数据，如，我们定义：


| 0xCC (帧头) | 0x03 (长度) | 数据1 | 数据2 | 数据3 |
|-------------|-------------|-------|-------|-------|
| 1 字节      | 1 字节      | 1 字节 | 1 字节 | 1 字节 |

这样我们可以先接收前两帧数据，然后便知道了数据的总长度

数据帧也可以有一个帧尾“\r\n”用来判断帧结束，通过这种方式，我们可以知道数据帧是否已经结束，我称这种数据是带特征的数据

但是有时候，比如我们与一个购买的模块通信，那个模块已经定好了通信方式，我们不能更改，然后他的数据长度是不定的，也没有帧尾可以用来判别，这种称为无特征的不定长度数据

## 什么是空闲中断

- 当串口没有数据来时，就是空闲状态
- 如果串口连续一帧的时间内，没有新的数据来，STM32 的硬件便可以产生中断
- 如果是其他芯片，或者其他没有空闲中断的使用场景，可以使用定时器每隔一段时间查看有没有新增数据，通过这种方式也可以模拟空闲中断

### HAL_UARTEx_ReceiveToIdle_DMA() 详解

```c
HAL_UARTEx_ReceiveToIdle_DMA(&huart1, rx_buffer, 10);
```
配套回调函数

```
volatile uint8_t rx_flag = 0;
volatile uint16_t rx_len = 0;
uint8_t rx_buffer[10];

void HAL_UARTEx_RxEventCallback(UART_HandleTypeDef *huart, uint16_t Size)
{
    if (huart->Instance == USART1)
    {
        rx_len = Size;      // 保存长度
        rx_flag = 1;        // 置标志，通知主循环
        
        // 重新启动 DMA
        HAL_UARTEx_ReceiveToIdle_DMA(&huart1, rx_buffer, 10);
    }
}

// 主循环
while (1)
{
    if (rx_flag)
    {
        rx_flag = 0;
        process_data(rx_buffer, rx_len);  // 在主循环中处理
    }
}
```

双缓冲

```
uint8_t rx_buffer[2][10];  // 双缓冲
uint8_t active_buf = 0;

void HAL_UARTEx_RxEventCallback(UART_HandleTypeDef *huart, uint16_t Size)
{
    if (huart->Instance == USART1)
    {
        // 切换到另一个缓冲区
        active_buf ^= 1;
        HAL_UARTEx_ReceiveToIdle_DMA(&huart1, rx_buffer[active_buf], 10);
        
        // 主循环处理旧缓冲区
        rx_flag = 1;
        rx_len = Size;
    }
}
```
###  DMA 半完成中断问题详解

DMA传输数据时，当传输进度到达预设总长度的一半时，硬件会自动触发一个中断信号，这个中断被称为 **半完成中断（Half Transfer Interrupt）**。

这导致在 `HAL_UARTEx_RxEventCallback` 回调中，**同一个数据包**会触发**两次**回调：
```c
// 预期接收 10 字节
HAL_UARTEx_ReceiveToIdle_DMA(&huart1, rx_buffer, 10);

// 回调函数会被调用两次
void HAL_UARTEx_RxEventCallback(UART_HandleTypeDef *huart, uint16_t Size)
{
    // 第 1 次：DMA 传输到一半时触发，Size = 5
    // 第 2 次：DMA 传输完成时触发，Size = 10
}
```
###  关闭 DMA 半传输中断

```c
HAL_UARTEx_ReceiveToIdle_DMA(&huart1, rx_buffer, 10);
__HAL_DMA_DISABLE_IT(huart1.hdmarx, DMA_IT_HT); // 关闭半传输中断
```

### 通过 HAL_UARTEx_GetRxEventType 区分中断类型
```
uint32_t HAL_UARTEx_GetRxEventType(UART_HandleTypeDef *huart);
```
| 返回值 | 宏定义 | 数值 | 含义 | 触发条件 |
|--------|--------|------|------|---------|
| `0x00000000U` | `HAL_UART_RXEVENT_HT` | 0 | 半传输中断 | DMA 传输完成一半时触发（如 10 字节收到 5 字节） |
| `0x00000001U` | `HAL_UART_RXEVENT_TC` | 1 | 传输完成中断 | DMA 传输完成，收满缓冲区全部字节时触发 |
| `0x00000002U` | `HAL_UART_RXEVENT_IDLE` | 2 | 空闲中断 | 总线空闲（一帧时间内无新数据）时触发 |


## 如何开启下一次的接收（时间和位置）？

### 方案一：处理完数据后再开启接收
```c
while (1)
{
    if (USART_DataIsReceived(&usart))
    {
        USART_DataResetReceivedFlag(&usart);
        uint8_t *data = USART_GetData(&usart);
        uint16_t len = USART_DataGetReceivedLen(&usart);
        
        // ★ 先处理数据（耗时操作）
        process_data(data, len);    // 可能耗时较长
        
        // ★ 处理完后再重新启动接收
        HAL_UARTEx_ReceiveToIdle_DMA(&huart1, rx_buffer, RX_BUFFER_SIZE);
        __HAL_DMA_DISABLE_IT(huart1.hdmarx, DMA_IT_HT);
    }
}
```
处理数据期间，新数据到来 → 硬件无缓冲区 → 丢包	   
确保处理时间 < 1帧时间（波特率越高，时间越短）


### 方案二：立即开启接收，再处理数据
```
void HAL_UARTEx_RxEventCallback(UART_HandleTypeDef *huart, uint16_t Size)
{
    if (huart->Instance == USART1)
    {
        // ★ 立即复制数据到安全区
        memcpy(process_buffer, rx_buffer, Size);
        
        // ★ 立即重新启动接收（不等处理完成）
        HAL_UARTEx_ReceiveToIdle_DMA(&huart1, rx_buffer, RX_BUFFER_SIZE);
        __HAL_DMA_DISABLE_IT(huart1.hdmarx, DMA_IT_HT);
        
        // ★ 再处理数据（此时接收已恢复）
        process_data(process_buffer, Size);
    }
}
```

处理数据期间，新数据到来 → DMA 写入 rx_buffer → 数据覆盖	

① 立即复制数据到安全区（双缓冲） ② 使用环形缓冲区

# 缓冲区的意义和LIFO的实现

使用缓冲区把“数据接收”和“数据处理”分离。

##  乒乓缓冲区（Ping-Pong Buffer）

**乒乓缓冲区**是一种**双缓冲**技术，通过两个缓冲区交替工作，实现数据的**连续接收**和**无缝处理**，避免数据冲突。

> 一个缓冲区接收数据时，另一个缓冲区处理数据；两者交替切换，如同打乒乓球一样来回交替。

还是存在丢包问题，使用三缓冲区？

接收区（DMA写入）、处理区（CPU读取）、空闲区（备用）。接收、待处理、处理 三者分离


### Circular DMA + HT/TC 模拟双缓冲

部分 STM32 不支持 DMA 硬件双缓冲，可以使用：

```text
Circular DMA
    +
HT 半传输中断
    +
TC 全传输中断
    +
UART IDLE
```

实现类似 **Ping-Pong Buffer** 的效果。

---

### 1. 一个缓冲区分成两半

```c
#define UART_DMA_BUF_LEN  30

uint8_t RecvDMABuf[UART_DMA_BUF_LEN];
```

逻辑上分为：

```text
RecvDMABuf[30]

┌───────────────┬───────────────┐
│ 前半区 0~14   │ 后半区 15~29 │
└───────────────┴───────────────┘
       HT               TC
```

DMA 使用循环模式：

```c
hdma_usart1_rx.Init.Mode = DMA_CIRCULAR;
```

写满后自动回到数组开头：

```text
前半区 → 后半区 → 前半区 → 后半区 → ...
```

---

### 2. HT：处理前半区

DMA 写到缓冲区一半时触发：

```c
void HAL_UART_RxHalfCpltCallback(UART_HandleTypeDef *huart)
{
    UsartRxCheck(huart);
}
```

此时：

```text
CPU → 处理前半区
DMA → 继续写后半区
```

---

### 3. TC：处理后半区

DMA 写完整个缓冲区时触发：

```c
void HAL_UART_RxCpltCallback(UART_HandleTypeDef *huart)
{
    UsartRxCheck(huart);
}
```

此时：

```text
CPU → 处理后半区
DMA → 自动回到前半区继续写
```

因此形成：

```text
DMA写前半区 → HT → CPU处理前半区
DMA写后半区 → TC → CPU处理后半区
DMA写前半区 → ...
```

这就是用 **Circular DMA + HT/TC 模拟双缓冲**。

---

### 4. IDLE：处理不足半区的数据

如果只收到少量数据：

```text
Data Data Data ─────────
               ↑
              IDLE
```

还没有触发 HT 或 TC，因此需要 UART 空闲中断：

```c
static void UART_RxIdleCallBack(UART_HandleTypeDef *huart)
{
    UsartRxCheck(huart);
}
```

所以：

```text
HT   → 处理前半区
TC   → 处理后半区
IDLE → 处理剩余的不定长数据
```

---

### 5. 判断 DMA 当前写入位置

核心公式：

```c
NewPos = UART_DMA_BUF_LEN -
         __HAL_DMA_GET_COUNTER(huart->hdmarx);
```

即：

$$
NewPos = BufferSize - DMA_{Remaining}
$$

其中：

```text
OldPos → 上一次处理到的位置
NewPos → DMA 当前写到的位置
```

只需要处理：

```text
OldPos → NewPos
```

---

### 6. DMA 回绕处理

正常情况：

```text
0   OldPos          NewPos          N
|------|==============|-------------|
       新数据
```

代码：

```c
UsartProcessData(
    &RecvDMABuf[OldPos],
    NewPos - OldPos
);
```

DMA 回绕后：

```text
0   NewPos      OldPos              N
|======|----------|=================|
 新数据              新数据
```

需要分两段处理：

```c
UsartProcessData(
    &RecvDMABuf[OldPos],
    UART_DMA_BUF_LEN - OldPos
);

UsartProcessData(
    &RecvDMABuf[0],
    NewPos
);
```

最后更新：

```c
OldPos = NewPos;
```

## 核心思想

```text
UART
 ↓
Circular DMA
 ↓
一个缓冲区循环写入
 ↓
HT / TC / IDLE
 ↓
UsartRxCheck()
 ↓
根据 OldPos、NewPos
处理新增数据
```

> **HT 和 TC 将一个 Circular DMA 缓冲区逻辑上分成两半，实现类似双缓冲的交替处理；IDLE 用来补充处理没有达到半缓冲区边界的不定长数据。**


# LIFO缓冲区的实现

```c
uint8_t* usart_rx_buf[3];

uint8_t* writePtr;      // DMA 正在写
uint8_t* nextReadPtr;   // 已接收完成，等待处理
uint8_t* processPtr;    // CPU 正在处理

uint16_t readDataSize;
uint16_t processDataSize;
```

三个指针分别对应：

```text
writePtr     → 接收区
nextReadPtr  → 待处理区
processPtr   → 处理区
```

##  初始化三块缓冲区

传入一块连续内存，然后平均分成 3 份：

```c
this->rxSize_Max = rxSize_Max / 3;

this->usart_rx_buf[0] = rxBuffer;
this->usart_rx_buf[1] = rxBuffer + this->rxSize_Max;
this->usart_rx_buf[2] = rxBuffer + 2 * this->rxSize_Max;

this->writePtr = this->usart_rx_buf[0];
this->nextReadPtr = NULL;
this->processPtr = NULL;
```

例如：

```c
uint8_t uartBuf[300];
```

实际得到：

```text
Buffer 0 → 100 Byte
Buffer 1 → 100 Byte
Buffer 2 → 100 Byte
```

DMA 首先写入：

```text
writePtr → Buffer 0
```

##  寻找下一块可写 Buffer

```c
static uint8_t* getNextWritePtr(USART_Data* this)
{
    uint8_t* idleBuffer = NULL;

    for (int i = 0; i < 3; i++)
    {
        if (this->usart_rx_buf[i] != this->processPtr &&
            this->usart_rx_buf[i] != this->nextReadPtr)
        {
            idleBuffer = this->usart_rx_buf[i];
            break;
        }
    }

    return idleBuffer;
}
```

判断规则：

```text
不是 processPtr
+
不是 nextReadPtr
=
可以交给 DMA
```

例如：

```text
Buffer A → CPU处理
Buffer B → 等待处理
Buffer C → 空闲

writePtr → Buffer C
```

##  DMA 接收完成后切换 Buffer

关键代码位于：

```c
HAL_UARTEx_RxEventCallback()
```

核心逻辑：

```c
this->nextReadPtr = this->writePtr;
this->readDataSize = Size;

this->writePtr = getNextWritePtr(this);

HAL_UARTEx_ReceiveToIdle_DMA(
    this->huart,
    this->writePtr,
    this->rxSize_Max
);
```

执行过程：

```text
writePtr
   ↓
一帧接收完成
   ↓
nextReadPtr
   ↓
寻找空闲 Buffer
   ↓
新的 writePtr
   ↓
DMA 继续接收
```

例如：

```text
Buffer A → 收到 Frame1
Buffer B → 新的 DMA 接收区
Buffer C → 空闲
```

变为：

```text
Buffer A → nextReadPtr
Buffer B → writePtr
```

## CPU 锁定待处理数据

主程序需要处理数据时调用：

```c
uint8_t* uartDataProcessLock(USART_Data* this)
{
    this->processPtr = this->nextReadPtr;
    this->processDataSize = this->readDataSize;

    this->nextReadPtr = NULL;

    return this->processPtr;
}
```

本质就是：

```text
nextReadPtr
     ↓
processPtr
```

此后 `getNextWritePtr()` 不会再把这个 Buffer 分配给 DMA。

---

##  处理完成后释放

```c
void uartDataProcessUnlock(USART_Data* this)
{
    this->processPtr = NULL;
}
```

表示 CPU 已经处理完成，该 Buffer 可以重新用于 DMA。

---

##  使用方式

```c
if (USART_DataIsReceived(&uart))
{
    uint8_t *data;
    uint16_t len;

    /* 获取并锁定数据 */
    data = uartDataProcessLock(&uart);

    /* 获取数据长度 */
    len = USART_DataGetReceivedLen(&uart);

    /* 数据处理 */
    DataProcess(data, len);

    /* 释放 Buffer */
    uartDataProcessUnlock(&uart);
}
```

完整流程：

```text
DMA → writePtr
        ↓
     收到一帧
        ↓
  nextReadPtr
        ↓
      Lock
        ↓
   processPtr
        ↓
    CPU处理
        ↓
     Unlock
```

---

##  所谓 LIFO

这份代码中的 `LIFO` 更接近：

> **只保留最新的待处理数据。**

如果：

```text
Frame1 → CPU正在处理
Frame2 → 等待处理
Frame3 → 又接收完成
```

执行：

```c
this->nextReadPtr = this->writePtr;
```

后：

```text
Frame2 → 被旧化
Frame3 → 成为新的 nextReadPtr
```

因此适合：

```text
遥控数据
IMU 数据
速度 / 位置
传感器实时值
```

因为这类场景通常更关心**最新一帧**。

---

## 核心记忆

```c
writePtr       // DMA写
nextReadPtr    // 等待CPU处理
processPtr     // CPU正在处理
```

三缓冲区的核心就是：

> **接收、等待、处理三者分离，DMA 不覆盖 CPU 正在处理的数据。**
