## 在 ISR 中调用 malloc() 一般是不推荐

- malloc() 执行时间不确定。它可能需要遍历空闲链表、合并内存块，耗时不可预测，而 ISR 要求尽量短、确定性强。
- malloc() 通常不是中断安全的。很多 C 库的堆管理内部会使用全局数据结构或锁。如果主线程正在执行 malloc() 时被中断，ISR 又调用一次，可能导致堆结构被破坏，甚至死锁。
- 容易产生内存碎片。嵌入式系统 RAM 很小，频繁动态申请和释放会让堆越来越碎，长期运行可靠性差。
- 可能影响实时性。ISR 中做动态内存管理会延长中断响应时间，影响其他更高优先级任务或中断。

## RISC-V和ARM架构区别

-  ARM 是商业授权架构，指令集和核心设计由 Arm 公司主导，生态非常成熟，广泛应用在手机、MCU、嵌入式和服务器。
- RISC-V 是开放指令集 ISA，本身免费、开放，厂商可以基于标准指令集自行设计 CPU，也可以增加自定义扩展。

## 汇编怎么读寄存器

普通 CPU 寄存器直接通过 MOV/mv 使用；内存映射外设寄存器用 LDR/LW；ARM 系统寄存器通常用 MRS，RISC-V 的 CSR 用 CSRR 系列指令。

## Flash擦写
Flash 不能直接把 0 改回 1，所以本质上都需要先擦后写。“边写边擦”是按 Sector 边擦边写，启动快但写入过程中可能被擦除操作阻塞；“擦完再写”是先把目标区域全部擦除，再连续编程，写入过程更稳定，但前期等待时间更长。





## 智能指针

C++ 智能指针主要是用 RAII 自动管理动态内存，避免手动 new/delete 带来的内存泄漏。

常见有三个：
unique_ptr 是独占所有权，不能拷贝，只能移动；
shared_ptr 是共享所有权，通过引用计数管理对象生命周期；
weak_ptr 是弱引用，不增加强引用计数，主要用于解决 shared_ptr 的循环引用。

实际项目中我一般优先使用 unique_ptr，确实需要共享所有权时再使用 shared_ptr。

## Bootloader 中升级和 APP 中升级有什么区别

Bootloader 升级和 APP 升级的主要区别是**升级代码运行的位置和可靠性**。

Bootloader 升级是在独立的 Bootloader 区运行，可以直接擦写 APP，即使 APP 损坏也能重新升级，可靠性更高。

APP 升级是在应用程序中完成下载和校验，一般不会直接覆盖自己，而是设置升级标志后重启，再由 Bootloader 完成固件替换。

简单来说：**APP 负责下载和触发升级，Bootloader 负责真正更新程序和保证升级安全。**

## 高可靠 OTA 怎么保证？每个数据包怎么保证可靠？

高可靠 OTA 我一般分两层保证。

第一层是单包可靠，每个数据包都会带包序号、长度和 CRC。接收端校验通过就回复 ACK，校验失败或者丢包就重传，这样可以保证数据不丢、不乱、不重复。

第二层是整包可靠，固件下载完成以后会再做一次整体 CRC、Hash 或签名校验。

另外为了防止升级过程中掉电，一般会用 A/B 分区或者备份区，新固件验证成功以后再切换。如果新版本启动失败，还可以自动回滚到旧版本。

简单来说就是：**单包靠序号、CRC 和重传，整包靠完整性校验，系统层面靠 A/B 和回滚防止变砖。**

## I2C 采集任务优先级怎么设计？多任务怎么保护临界资源？

I2C 采集任务的优先级，我一般根据**采样周期和实时性要求**来定。

如果这个传感器数据是控制环或者保护逻辑要用的，我会把采集任务优先级设高一些；如果只是温度、电量这类慢速数据，优先级可以低一些。一般不会把 I2C 任务设成系统最高优先级，避免 I2C 通信时间比较长，把其他关键任务堵住。

多任务访问临界资源时，比如多个任务共用同一个 I2C 总线，我会加 **Mutex 互斥锁**，谁拿到锁谁访问 I2C，用完立即释放。

如果是很短的共享变量操作，可以用临界区或者关中断保护；如果是任务间同步，可以用信号量、事件或者消息队列。

另外用 Mutex 的话，最好支持**优先级继承**，避免出现优先级反转。

简单来说就是：**任务优先级按实时性来排，共享 I2C 用 Mutex，短临界资源用临界区，任务同步用信号量或队列。**

## 优先级继承后任务怎么调度？什么时候触发任务调度？

优先级继承主要是解决**优先级反转**。

比如低优先级任务 L 拿着 Mutex，高优先级任务 H 也来申请这个 Mutex，这时候 H 会被阻塞。RTOS 会临时把 L 的优先级提升到 H 的优先级，让 L 尽快把临界区执行完并释放 Mutex。

Mutex 释放以后，L 的优先级会恢复到原来的优先级，然后 H 变成就绪态。如果 H 的优先级比当前任务高，就会马上触发任务切换，开始执行 H。

任务调度一般会在这几种情况下触发：**高优先级任务进入就绪态、当前任务阻塞或延时、释放信号量或 Mutex 唤醒了高优先级任务、时间片到期，以及中断退出时发现有更高优先级任务就绪。**

简单来说就是：**优先级继承让低优先级任务临时“提速”释放资源，资源释放后再恢复优先级，并调度当前最高优先级的就绪任务。**


## 日志里想打印具体耗时，怎么实现？

普通任务耗时用 RTOS Tick，精确性能分析使用 DWT Cycle Counter。
```
TickType_t start = xTaskGetTickCount();

func();

TickType_t end = xTaskGetTickCount();

耗时 = (end-start) × portTICK_PERIOD_MS
```
---
```
uint32_t start = DWT->CYCCNT;

func();

uint32_t cycles = DWT->CYCCNT - start;

time = cycles / CPU主频
```



## RTOS 中断怎么保护共享资源？中断修改全局变量有问题吗？

RTOS 里如果中断和任务会同时访问同一个共享资源，我一般会根据资源类型做保护。

如果只是很短的共享变量操作，可以在任务侧进入临界区或者短时间关中断，避免任务访问过程中被中断打断。

中断里一般不能直接用普通 Mutex，因为 Mutex 可能导致阻塞，中断上下文不能睡眠。通常要用 RTOS 提供的 ISR 接口，比如 FromISR 的信号量、队列或者事件通知，把数据通知给任务处理。

中断修改全局变量本身不是一定有问题，关键看它是不是被任务同时访问。如果同时读写，就可能出现竞争条件。除了加 volatile 保证每次都从内存访问之外，还要考虑原子性和同步问题，volatile 本身并不能保证线程安全。

简单来说就是：**中断里尽量少做事，共享数据要做临界区或原子保护，复杂处理通过队列、信号量通知任务来完成。**

## 什么时候会发生页表错误 / Page Fault

Page Fault 本质上就是 CPU 访问某个虚拟地址时，MMU 查页表发现这个地址当前不能正常完成访问，于是触发异常。

常见情况有几种：第一种是这个虚拟页还没有映射到物理内存，比如按需分页，第一次访问时会触发 Page Fault，操作系统再把页面加载进来。

第二种是页面被换出到磁盘了，访问时需要重新换入内存。

第三种是权限不对，比如只读页被写、用户态访问内核地址，或者访问了不可执行页面。

还有一种就是访问非法地址，比如空指针、野指针或者已经释放的内存，这种 Page Fault 通常无法恢复，最后可能导致进程崩溃。

简单来说就是：**地址没映射、页面不在内存、访问权限错误或者地址非法，都可能触发 Page Fault。**


## 为什么使用 IDLE 中断，而不用普通接收中断？

如果是 UART 接收，我用 IDLE 中断主要是为了处理**不定长数据**。

普通接收中断一般是每收到一个字节就进一次中断，数据量大的时候中断会很频繁，CPU 开销比较大。

IDLE 中断可以配合 DMA 使用，DMA 负责连续接收数据，当串口一段时间没有新数据、出现空闲帧时，再触发一次 IDLE 中断。这时候根据 DMA 剩余计数就能算出实际收到多少字节。

这样做的优点就是：**中断次数少、CPU 占用低，而且很适合不定长协议。**

简单来说就是：**普通接收中断偏逐字节处理，IDLE + DMA 更适合高吞吐、不定长数据接收。**


## malloc/free和new/delete的区别

`malloc/free` 是 C 语言的动态内存管理，`new/delete` 是 C++ 的。最大的区别是，`malloc` 只负责申请一块指定字节大小的内存，不会调用构造函数，`free` 也不会调用析构函数；而 `new` 在申请内存后会调用构造函数，`delete` 会先调用析构函数再释放内存。

另外，`malloc` 返回的是 `void*`，分配失败一般返回 `NULL`；`new` 返回对应类型的指针，默认分配失败会抛出 `std::bad_alloc`。使用时一定要配对：`malloc` 对 `free`，`new` 对 `delete`，`new[]` 对 `delete[]`，不能混用。

## 写一个大小端判断程序

我可以定义一个多字节整数，比如 0x12345678，然后把它的地址强转成 char*，读取最低地址的一个字节。如果读到 0x78，说明低地址存低有效字节，是小端；如果读到 0x12，说明低地址存高有效字节，是大端。

```
#include <stdio.h>

int main(void)
{
    unsigned int num = 0x12345678;
    unsigned char *p = (unsigned char *)&num;

    if (*p == 0x78)
        printf("Little Endian\n");
    else if (*p == 0x12)
        printf("Big Endian\n");

    return 0;
}
```

## static 关键字有什么作用？
static 主要看三个场景。修饰局部变量时，变量生命周期变成整个程序运行期间，只初始化一次，但作用域仍然在函数内部；修饰全局变量时，会限制它只能在当前源文件中访问；修饰函数时，同样限制函数只能在当前 .c 文件内部调用，主要用于隐藏模块内部实现。

## const 和 volatile 分别有什么作用？为什么中断和寄存器要用 volatile？
const 表示程序不应该通过当前变量去修改它，主要用于只读保护。volatile 表示这个变量可能被程序当前执行流程之外的因素改变，告诉编译器每次都必须真正从内存读取，不能使用寄存器里的缓存值。

比如中断修改的全局变量、硬件寄存器、DMA 修改的状态变量，都经常需要 volatile。

例如：
~~~
volatile uint8_t flag = 0;
~~~

主循环：
~~~
while(flag == 0);
~~~
如果没有 volatile，编译器可能认为 flag 没有变化，把它优化成死循环。

但要注意：volatile 不能保证原子性，也不能解决线程安全问题。


## 什么是内存泄漏？怎么避免？

内存泄漏就是：

申请了一块动态内存，但是没有释放，而且程序又丢失了这块内存的地址。

例如：
~~~
char *p = malloc(100);

p = malloc(200);
~~~
第一块 100 字节内存的地址丢失了，就泄漏了。

避免方法主要是：

谁申请谁释放；
明确内存所有权；
每个 malloc 对应 free；
C++ 优先使用 RAII 和智能指针；
避免频繁动态分配。

嵌入式项目里我会尽量使用静态内存或者预先分配固定内存池。

## strcpy 和 strncpy 有什么区别？memcpy 和 strcpy 有什么区别？memcmp 和 strcmp 有什么区别？

strcpy 和 strncpy 都是字符串复制，区别是 strncpy 可以限制长度，但可能不会自动补 '\0'。

memcpy 和 strcpy 的区别是，strcpy 按 '\0' 判断字符串结束，而 memcpy 不关心数据内容，只复制指定字节数。

memcmp 和 strcmp 类似，strcmp 比较字符串，遇到 '\0' 停止；memcmp 比较内存块，会严格比较指定的 n 个字节。

## strncmp 有什么作用？

strncmp 的作用是比较两个字符串的前 n 个字符。它会从头逐个字符比较，最多比较 n 个，或者遇到字符串结束符 '\0' 就停止。如果返回 0，说明这部分相等；小于 0 说明第一个字符串更小；大于 0 说明第一个字符串更大。相比 strcmp，strncmp 多了一个长度限制，可以避免无限制地往后比较。

## 如何把一个变量中的某一 bit 取反？

如果要把一个变量中的某一位 bit 取反，我会用异或运算。

比如要把 n 的第 k 位取反，可以写：

~~~
n ^= (1 << k);
~~~

因为异或的特点是，和 1 异或会取反，和 0 异或保持不变。

1 << k 就是构造一个只有第 k 位是 1 的掩码，所以和 n 异或以后，只会翻转第 k 位，其他位不受影响。

时间复杂度是 O(1)。

## 如何判断一个数是不是 2 的若干次幂？

2 的幂在二进制中只有一个 1，而 n - 1 会把这个 1 变成 0，并把后面的位全部变成 1，所以 n & (n - 1) 一定等于 0。因此判断条件是 n > 0 && (n & (n - 1)) == 0，时间复杂度 O(1)，空间复杂度 O(1)。
~~~
boolean isPowerOfTwo(int n) {
    return n > 0 && (n & (n - 1)) == 0;
}
~~~


##  USB 枚举的作用是什么？过程是什么？

USB 枚举简单说，就是主机插入 USB 设备以后，识别“你是谁、你有什么功能”，然后给设备分配地址并加载对应驱动的过程。

设备插入以后，Host 首先检测设备连接并复位设备，这个时候设备默认地址是 0。
然后主机会读取设备描述符，知道它的 VID、PID、设备类型这些信息。

接着主机通过 Set Address 给设备分配一个新的 USB 地址，再继续读取配置描述符、接口描述符、端点描述符等。

最后选择配置并加载对应驱动，之后设备才算正式进入正常通信状态。


## NAND Flash 的 spare area 里，ECC 是干什么的？

NAND Flash 一个 Page 一般分成数据区和 Spare/OOB 区。
Spare Area 一般会保存 ECC 校验码、坏块标记以及一些文件系统或者 Flash 管理需要的元数据。

因为 NAND Flash 使用过程中可能出现 bit flip，也就是某几个 bit 发生错误，所以写数据的时候会计算 ECC 并保存；读取的时候再重新计算 ECC，和之前保存的 ECC 对比。

如果错误在 ECC 的纠错能力范围内，就可以把数据纠正回来；超过纠错能力就会认为这个 Page 数据不可靠。

## 单片机中的 NAND Flash 怎么和文件系统对接？
NAND 不能简单地像 RAM 一样直接读写，因为它有 Page、Block、擦除、坏块以及寿命这些问题。

所以一般会在 NAND 驱动和文件系统之间增加一层 Flash 管理层，比如做坏块管理、ECC、磨损均衡以及逻辑地址到物理地址的映射。

文件系统看到的是逻辑块或者统一的读写接口，底层再把它转换成实际的 Page Read、Page Program、Block Erase。

在 Linux 里面比较典型的是 MTD、UBI，再上面挂 UBIFS；如果是单片机，也可以根据系统资源选择 LittleFS 之类比较适合 Flash 的文件系统。

## 怎么防止头文件重复包含？

~~~
#ifndef __TEST_H__
#define __TEST_H__

// header content

#endif
~~~
一般使用宏保护，也就是 #ifndef、#define、#endif。

第一次包含的时候这个宏没有定义，就进入头文件并定义宏；后面再次 include 时发现宏已经定义了，就不会再次展开。

另外有些编译器也支持 #pragma once，写起来更简单，不过宏保护的兼容性更好。

## 手写冒泡排序，并说明时间、空间复杂度

~~~
void bubble_sort(int a[], int n)
{
    for (int i = 0; i < n - 1; i++)
    {
        int swapped = 0;

        for (int j = 0; j < n - 1 - i; j++)
        {
            if (a[j] > a[j + 1])
            {
                int temp = a[j];
                a[j] = a[j + 1];
                a[j + 1] = temp;
                swapped = 1;
            }
        }

        if (!swapped)
            break;
    }
}
~~~

## 死锁产生的四个必要条件是什么？怎么预防？

第一，互斥条件，一个资源同一时刻只能被一个任务占用。
第二，请求并保持，任务拿着一个资源，又去请求另一个资源。
第三，不可剥夺，已经获得的资源不能被强制抢走。
第四，循环等待，多个任务形成一个资源等待环。

四个条件同时满足才有可能发生死锁。
