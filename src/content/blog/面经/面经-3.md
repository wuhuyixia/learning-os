# 面经（三）


## 判断链表是否有环

常用**快慢指针法**：

```c
int hasCycle(struct ListNode *head)
{
    struct ListNode *slow = head;
    struct ListNode *fast = head;

    while (fast && fast->next) {
        slow = slow->next;
        fast = fast->next->next;

        if (slow == fast)
            return 1;
    }

    return 0;
}
```

原理：

* 慢指针每次走 1 步
* 快指针每次走 2 步
* 如果有环，两者最终会相遇

时间复杂度：`O(n)`
空间复杂度：`O(1)`


## 什么时候使用多进程，什么时候使用多线程

多进程和多线程主要看**隔离性、通信成本、任务类型**。

| 场景      | 多进程 | 多线程            |
| ------- | --- | -------------- |
| 需要高隔离   | 适合  | 不适合            |
| 数据共享多   | 较麻烦 | 适合             |
| 通信频繁    | 开销大 | 开销小            |
| 稳定性要求高  | 适合  | 一个线程崩溃可能影响整个进程 |
| 创建/切换开销 | 大   | 小              |

常见选择：

* **多进程**：服务端多个独立任务、需要故障隔离。
* **多线程**：同一程序内多个任务并发、频繁共享数据。

核心：**重隔离用多进程，重共享和效率用多线程。**


## 软件IIC和硬件IIC的区别

| 对比     | 软件 IIC     | 硬件 IIC       |
| ------ | ---------- | ------------ |
| 实现     | GPIO 模拟时序  | MCU IIC 外设实现 |
| CPU 占用 | 较高         | 较低           |
| 速度     | 较慢         | 较快           |
| 灵活性    | 高，可任意 GPIO | 受固定引脚限制      |
| 开发难度   | 简单直观       | 配置相对复杂       |
| 稳定性    | 依赖软件时序     | 一般更稳定        |

核心：**软件 IIC 灵活，硬件 IIC 效率高、CPU 占用低。**


## Linux和RTOS的区别


| 对比  | Linux                 | RTOS                       |
| --- | --------------------- | -------------------------- |
| 实时性 | 一般                    | 强，响应时间可预测                  |
| 体积  | 较大                    | 较小                         |
| 功能  | 丰富                    | 精简                         |
| 调度  | 注重吞吐量、公平性             | 注重实时任务优先级                  |
| 应用  | PC、服务器、复杂嵌入式          | 单片机、工业控制、实时设备              |
| 代表  | Ubuntu、Embedded Linux | FreeRTOS、RT-Thread、VxWorks |

核心区别：**Linux 重功能，RTOS 重实时性。**

## 取消内存对齐的方法

常见取消内存对齐的方法：

```c
#pragma pack(1)

struct A {
    char a;
    int b;
};

#pragma pack()
```

GCC 还可写：

```c
struct __attribute__((packed)) A {
    char a;
    int b;
};
```

作用：让结构体成员按 **1 字节对齐**，减少填充字节。


## 使用C语言实现strcat函数

strcat 用于把一个字符串追加到另一个字符串末尾。
```c
char *my_strcat(char *dest, const char *src)
{
    char *p = dest;

    while (*p)
        p++;

    while ((*p++ = *src++))
        ;

    return dest;
}
```
## 使用C语言编写一个strcmp函数

strcmp 是 C 语言中用来比较两个字符串大小的函数
```c
int my_strcmp(const char *s1, const char *s2)
{
    while (*s1 && *s1 == *s2) {
        s1++;
        s2++;
    }

    return *(unsigned char *)s1 - *(unsigned char *)s2;
}
```

返回值：

* `< 0`：`s1 < s2`
* `= 0`：两字符串相等
* `> 0`：`s1 > s2`


## 大小端的概念和判断

小端：小的那一端（低位字节）放在小地址
大端：大的那一端（高位字节）放在小地址

~~~
#include <stdio.h>

int main(void)
{
    int x = 1;

    char *p = (char *)&x;

    if (*p == 1)
        printf("小端\n");
    else
        printf("大端\n");

    return 0;
}
~~~

## FreeRTOS任务的状态

FreeRTOS 任务主要有 4 种状态：

* **Running（运行态）**：正在占用 CPU。
* **Ready（就绪态）**：可以运行，等待 CPU。
* **Blocked（阻塞态）**：等待延时、信号量、队列等事件。
* **Suspended（挂起态）**：被主动挂起，不能参与调度。

核心：**运行、就绪、阻塞、挂起。**


## RTOS中时间片的大小

RTOS 中时间片大小通常由**系统时钟节拍 Tick** 决定。

以 FreeRTOS 为例：

```c
#define configTICK_RATE_HZ 1000
```

表示：

```text
1 Tick = 1ms
```

同优先级任务通常按 **1 个 Tick** 轮转一次。


## RTOS中任务同步的方式

RTOS 中常见任务同步方式：

* **信号量**：二值信号量、计数信号量
* **互斥锁**：保护共享资源
* **事件标志组**：等待多个事件
* **消息队列**：任务间传递数据并同步
* **任务通知**：轻量、高效

核心：**信号量、互斥锁、队列、事件组、任务通知。**

## FreeRTOS的调度算法

FreeRTOS 主要采用：

* **抢占式优先级调度**：高优先级任务可以抢占低优先级任务。
* **同优先级时间片轮转**：多个同优先级任务轮流运行。
* **协作式调度**：可配置，任务主动让出 CPU。

核心：**优先级抢占 + 同优先级时间片轮转。**


## 什么是僵尸进程，孤儿进程，守护进程

* **僵尸进程**：子进程已经结束，但父进程还没回收它的退出状态，进程表项仍存在。
* **孤儿进程**：父进程先退出，子进程还在运行，会被 `init/systemd` 接管。
* **守护进程**：长期在后台运行、通常不与终端关联的进程，如 `sshd`、`cron`。

核心：
**僵尸：死了没收尸；孤儿：父进程没了；守护：后台长期运行。**


## 进程有几个状态
Linux 进程常见有 **5 种基本状态**：

* **R 运行/就绪**：正在运行或等待 CPU
* **S 可中断睡眠**：等待事件
* **D 不可中断睡眠**：通常等待 I/O
* **T 停止**：进程被暂停
* **Z 僵尸**：已退出，但父进程未回收

另外还有 `X`：死亡状态，通常看不到。([man7.org][1])

核心：**运行、睡眠、不可中断、停止、僵尸。**


## Linux 进程间通信常见方式：

* 管道 `pipe`
* 命名管道 `FIFO`
* 消息队列
* 共享内存
* 信号 `signal`
* 信号量
* Socket

其中：

* **管道、消息队列、信号、信号量、Socket**：通信过程需要内核参与。
* **共享内存**：建立时需要内核，建立后进程可直接访问内存，效率最高。

核心：**共享内存数据传输时内核参与最少。**

## 什么是内联函数，为什么要有内联函数

内联函数：用 `inline` 修饰，编译器可将**函数代码直接展开到调用处**。

```c
inline int add(int a, int b)
{
    return a + b;
}
```

作用：

* 减少函数调用、压栈出栈开销
* 提高短小、频繁调用函数的执行效率

缺点：可能增加代码体积。

核心：**用空间换时间。**

## 在资源受限的嵌入式环境下，程序出现偶发性死机且无法连接调试器，你会怎么排查？

可以按下面顺序排查：

1. **看门狗**：开启 Watchdog，死机后自动复位，并记录复位原因。
2. **日志记录**：通过串口、Flash、RAM 保留关键运行日志。
3. **检查栈溢出**：查看任务栈大小、高水位，开启 FreeRTOS 栈溢出检测。
4. **检查内存**：排查越界、野指针、内存泄漏、堆耗尽。
5. **检查中断**：中断是否执行过久、优先级错误、死循环。
6. **检查死锁**：互斥锁、信号量是否存在永久等待。
7. **检查硬件**：电源、电压、时钟、EMI、温度等。
8. **保存现场**：HardFault 时保存 `PC、LR、SP` 等寄存器到 Flash，重启后分析。

核心：**先保存死机现场，再从栈、内存、中断、死锁、硬件逐项排查。**

## 讲一下你对内存管理的理解，栈和堆在嵌入式中分别怎么用？需要注意什么？

内存管理就是合理分配和使用有限的 RAM，避免**越界、泄漏、碎片和栈溢出**。

* **栈（Stack）**：存放局部变量、函数参数、返回地址等，自动分配和释放，速度快，但空间有限。
* **堆（Heap）**：用于动态内存分配，如 `malloc/free`，使用灵活，但容易产生内存泄漏和碎片。

嵌入式中注意：

* 栈不能开太大的局部数组，防止栈溢出。
* `malloc` 后必须及时 `free`。
* 实时系统中尽量少用动态内存，避免碎片和分配时间不确定。
* FreeRTOS 要合理设置每个任务的栈大小，并检查栈高水位。

核心：**栈快且确定，堆灵活但风险更高；嵌入式更强调内存可控。**

## 未接收到串口数据，如何查错

排查串口未收到数据，一般按下面顺序：

* **硬件**：检查 TX/RX 是否接反、是否共地、电平是否匹配。
* **串口参数**：检查波特率、数据位、停止位、校验位是否一致。
* **GPIO 配置**：确认引脚复用、输入输出模式是否正确。
* **发送端**：用示波器/逻辑分析仪看 TX 是否真的有波形。
* **接收方式**：检查轮询、中断或 DMA 是否正确开启。
* **中断**：确认串口中断使能、NVIC 配置、ISR 是否进入。
* **状态标志**：检查 RXNE、ORE、FE 等错误标志。
* **软件逻辑**：检查接收缓冲区、指针越界、数据是否被覆盖。

核心：**先看有没有波形，再查参数、GPIO、中断/DMA和软件逻辑。**


## RS232 和 RS485 的区别

| 对比   | RS232 | RS485     |
| ---- | ----- | --------- |
| 传输方式 | 单端    | 差分        |
| 通信距离 | 短     | 长         |
| 抗干扰  | 较差    | 强         |
| 通信节点 | 点对点   | 支持多节点     |
| 双工   | 全双工   | 常见半双工     |
| 典型距离 | 约 15m | 可达约 1200m |

核心：**RS232 适合短距离点对点，RS485 适合远距离、多节点、强干扰环境。**
