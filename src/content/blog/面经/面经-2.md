# 面经(二)



##  malloc、calloc、realloc

malloc、calloc、realloc 都用于动态内存管理，主要区别是：

malloc(size)：分配一块指定字节数的内存，不初始化，里面是未定义值。
calloc(n, size)：分配 n * size 字节，并且清零初始化。
realloc(ptr, new_size)：对已经分配的内存扩容或缩容，原有数据会尽量保留，必要时可能搬到新的地址。

补充一点：三者分配失败都会返回 NULL，使用完都要 free()。realloc 最好用临时指针接收，避免失败时丢失原指针。


## volatile 关键字有什么作用？嵌入式中什么时候使用
volatile 是用来告诉编译器，这个变量可能会在当前程序执行流程之外发生变化，因此每次访问都要实际进行内存或寄存器读写，不能因为编译器认为值没变化就把访问优化掉。嵌入式里主要用于三类场景：第一，中断服务函数和主程序共享的变量；第二，硬件寄存器或者 MMIO；第三，DMA 等硬件可能异步修改的数据。需要注意的是，volatile 只能解决编译器优化相关的问题，不能保证原子性，也不能代替锁或者临界区。


## 中断从触发到进入中断服务函数，这个过程是怎样的?
以 Cortex-M 为例，外设事件发生后会设置中断标志，如果外设中断使能，就向 NVIC 发出 IRQ。NVIC 根据中断使能、优先级和当前屏蔽状态判断是否响应。CPU响应后会完成当前指令，然后硬件自动把 R0-R3、R12、LR、PC 和 xPSR 等寄存器压栈保存现场，再根据中断号从中断向量表中取出 ISR 地址并跳转执行。ISR 中一般需要处理事件并清除中断标志。ISR结束后通过异常返回机制，CPU自动恢复之前保存的现场，然后继续执行被中断的程序。

## 什么是SMP
SMP 是 Symmetric Multiprocessing，也就是对称多处理。它通常指多个 CPU 核由同一个操作系统统一管理，各个核地位基本对等，任务可以运行在不同 CPU 上，甚至可以在不同 CPU 之间迁移。由于多个核能够并行访问共享内存，所以 SMP 系统需要重点处理并发和同步问题，比如 atomic、spinlock、mutex，同时还要考虑 Cache 一致性和内存屏障。它和 AMP 的区别在于，AMP 中不同 CPU 往往承担不同功能，甚至运行不同的操作系统。

## PendSV 是干什么的

PendSV 是 Cortex-M 提供的一种可挂起异常，RTOS 通常用它完成任务上下文切换。它一般被设置成最低优先级。当 SysTick 或其他中断发现需要进行任务调度时，不直接在当前中断里完成切换，而是把 PendSV 设置为 pending。等更高优先级中断全部执行完成后，CPU进入 PendSV。进入 PendSV 时硬件自动保存 R0-R3、R12、LR、PC 和 xPSR，PendSV 再通过软件保存 R4-R11以及当前任务的 PSP，调度器选择下一个任务后加载新任务的 PSP并恢复寄存器，最后异常返回，从而实现任务切换。

## FreeRTOS和RTThread的区别

FreeRTOS 更偏向轻量级实时内核，主要提供任务调度、队列、信号量、互斥锁、事件组和软件定时器等基础功能，内核小、移植广，非常适合资源受限的 MCU。RT-Thread 除了 RTOS 内核之外，还提供比较完整的设备驱动框架、文件系统、网络、Shell、POSIX兼容和软件包生态，因此更像一个完整的嵌入式操作系统平台。两者都支持基于优先级的抢占式实时调度。如果项目比较简单、资源有限，我会倾向 FreeRTOS；如果外设和中间件比较多、希望系统组件统一管理，RT-Thread会更方便。

## C语言位域

位域是 C 语言结构体的一种成员定义方式，可以指定成员占用的 bit 数，比如 unsigned int flag : 1 表示只使用 1 bit。嵌入式里经常用它描述状态字段或者硬件寄存器字段。

位域的具体内存布局具有实现相关性，比如位的分配方向、对齐和 padding 可能依赖编译器和 ABI，因此可移植性不好，不适合直接用作网络协议或跨平台存储格式。另外，对硬件寄存器进行位域写操作可能生成 read-modify-write，对于 W1C 等具有写副作用的寄存器需要特别小心。

因为位域成员可能只占一个存储单元中的几个 bit，而普通指针地址通常以字节为最小寻址单位，所以位域不是普通的可寻址对象。

## Cortex-M3 和Cortex-M4
Cortex-M3 基于 ARMv7-M 架构，而 Cortex-M4 基于 ARMv7E-M。两者的异常、中断、NVIC、SysTick、PendSV 等基础机制非常接近。M4 的主要增强是在 M3 基础上加入 DSP 指令扩展，包括 SIMD、乘加和饱和运算等，因此更适合电机控制、音频和数字信号处理。另外 Cortex-M4 可以选择集成单精度 FPU，带 FPU 的型号通常称为 Cortex-M4F，而 Cortex-M3 没有硬件 FPU。对于普通控制任务，两者差异可能不大，但对于 DSP 和浮点密集型算法，M4尤其是M4F会更有优势。

## 什么是原子操作

原子操作是指从并发执行的角度看不可再分割的操作，要么完整执行，要么不执行，其他线程、中断或者 CPU 核不能观察或干扰它的中间状态。例如 count++ 通常不是原子的，因为它实际上包含读、修改和写回三个步骤。在单核 MCU 上可以通过临界区或关中断保护这种操作，而在多核 SMP 系统中，仅关当前 CPU 中断是不够的，一般需要使用硬件原子指令、spinlock 或 mutex。Cortex-M3/M4 中还可以使用 LDREX/STREX 这类 exclusive 指令实现原子的读-改-写操作。

## TCP通信如何保证通信的可靠性

TCP 主要通过以下几个机制保证可靠传输：

1. **序列号和确认应答 ACK**
   TCP 给每个字节编号，接收方收到数据后返回 ACK，发送方通过 ACK 判断哪些数据已经成功到达。

2. **超时重传**
   如果发送方在规定时间内没有收到 ACK，就认为数据可能丢失，会重新发送。

3. **快速重传**
   如果发送方连续收到多个重复 ACK，说明某个报文段可能丢失，不等超时就立即重传，提高效率。

4. **校验和**
   TCP 报文中有校验和，用于检测数据在传输过程中是否发生错误。发现错误的数据会被丢弃，然后由发送端重传。

5. **滑动窗口和流量控制**
   接收方通过窗口大小告诉发送方自己还能接收多少数据，防止发送速度太快导致接收方缓存溢出。

6. **拥塞控制**
   TCP 通过慢启动、拥塞避免、快速重传、快速恢复等机制控制发送速率，避免网络发生严重拥塞和大量丢包。

7. **有序交付和去重**
   TCP 根据序列号对乱序报文重新排序，同时去掉重复数据，最终按正确顺序交给应用层。

一句话总结：

**TCP 通过序列号、ACK确认、超时/快速重传、校验和、滑动窗口、流量控制和拥塞控制，实现数据不丢、不重、不错、按序到达。**


## 为什么在FreeRTOs中信号量、队列等设计了两套函数?

FreeRTOS 中信号量、队列、任务通知等很多 API 都设计了两套，一套给普通任务使用，比如 `xQueueSend()`、`xSemaphoreGive()`；另一套是带 `FromISR` 的版本，比如 `xQueueSendFromISR()`、`xSemaphoreGiveFromISR()`。

核心原因是：**任务上下文和中断上下文的运行规则不同。**

第一，普通任务可以阻塞。比如队列满了，`xQueueSend()` 可以设置等待时间，让任务进入阻塞态，等队列有空间后再继续执行。但中断服务函数 ISR 不能阻塞，所以 `FromISR` 版本一定是立即返回的。

第二，调度方式不同。任务中调用普通 API 后，如果唤醒了更高优先级任务，FreeRTOS 可以正常进行调度；但在中断中不能直接随意切换任务，所以 `FromISR` API 会通过 `pxHigherPriorityTaskWoken` 告诉我们：这次操作是否唤醒了更高优先级任务，然后通过 `portYIELD_FROM_ISR()` 在退出中断时完成上下文切换。

第三，临界区和底层实现也不同。普通任务和 ISR 对中断屏蔽、临界区保护的要求不同，因此 FreeRTOS 必须分别提供适合两种上下文的实现。

所以总结就是：

**FreeRTOS 设计两套 API，是因为任务上下文允许阻塞和正常调度，而 ISR 上下文必须快速、非阻塞，并且任务切换要在中断退出时完成，因此需要专门的 `FromISR` 版本。**


## 什么是线程池

线程池就是：**提前创建一组线程，把需要执行的任务放到任务队列中，由空闲线程不断取任务执行，而不是每来一个任务就创建一个新线程。**

它主要解决两个问题：

1. **减少线程频繁创建和销毁的开销**
   线程创建、销毁需要消耗系统资源，线程池可以复用已有线程。

2. **限制线程数量，防止资源耗尽**
   如果任务很多，直接无限创建线程可能导致内存占用过大、上下文切换频繁，甚至系统崩溃。线程池通过固定或可控数量的线程来限制并发。

线程池一般包含：
**工作线程 + 任务队列 + 线程管理机制。**

基本流程是：
**任务提交到队列 → 空闲线程取任务 → 执行任务 → 执行完继续等待下一个任务。**

一句话总结：

**线程池本质上是一种线程复用和并发控制机制，用固定或可控数量的线程处理大量任务，从而降低线程创建销毁开销，并避免线程数量失控。**


## 讲解一下SON数据格式

JSON 是一种轻量级的数据交换格式，主要使用“键值对”的方式组织数据，特点是结构清晰、体积小、易于阅读，也方便程序解析。

例如：

```json
{
  "name": "Tom",
  "age": 20,
  "isStudent": true,
  "skills": ["C", "C++", "FreeRTOS"]
}
```

JSON 主要支持 6 种数据类型：

1. **字符串 String**
   `"name": "Tom"`

2. **数字 Number**
   `"age": 20`

3. **布尔值 Boolean**
   `"isStudent": true`

4. **空值 Null**
   `"address": null`

5. **对象 Object**
   使用 `{}` 表示，本质上是一组键值对。

6. **数组 Array**
   使用 `[]` 表示，可以保存多个元素。

JSON 中最重要的两个结构就是：

**对象：`{}`**

```json
{"name": "Tom", "age": 20}
```

**数组：`[]`**

```json
["C", "C++", "Python"]
```

在实际网络通信中，比如 HTTP、MQTT 或 TCP 应用层协议，经常会把结构化数据序列化成 JSON 字符串发送，接收方收到后再解析成程序中的对象或结构体。

一句话总结：

**JSON 是一种基于键值对的轻量级数据交换格式，主要由对象和数组组成，支持字符串、数字、布尔、null、对象和数组等数据类型，常用于前后端和网络设备之间的数据传输。**


## extern"C"的作用

extern "C" 主要用于解决 C 和 C++ 混合编程时的链接问题。因为 C++ 支持函数重载，编译器会对函数名进行 Name Mangling，而 C 不会。extern "C" 就是告诉 C++ 编译器按照 C 的方式生成和查找函数符号，这样 C++ 才能正确调用 C 编译出来的函数。它只改变链接方式，并不是把 C++ 代码变成 C 代码。

## Cache是什么?

Cache 是 CPU 和内存之间的一种高速缓存，用来缓解 CPU 和内存速度不匹配的问题。CPU 访问数据时先查 Cache，命中就直接使用，未命中再访问内存。它主要利用程序的时间局部性和空间局部性来提高访问效率。常见有 L1、L2、L3 Cache，越靠近 CPU 速度越快、容量通常越小。

## RAM，ROM，Flash的区别

RAM、ROM、Flash 最主要的区别是掉电是否保存以及能否修改。RAM 是易失性存储器，掉电数据丢失，但读写速度快，主要用于程序运行时的栈、堆和变量。ROM 是非易失性存储器，掉电不丢失，传统 ROM 一般写入后不能修改。Flash 也是非易失性存储器，但可以擦除和重新编程，所以嵌入式系统通常把程序代码存放在 Flash 中，运行时的数据放在 RAM 中。

## IP地址，子网掩码，网关，DNS的作用

IP 地址用于标识网络中的设备，相当于设备的网络地址；子网掩码用于区分网络号和主机号，并判断目标 IP 是否和自己在同一个网段；如果目标不在同一网段，就需要通过默认网关把数据转发到其他网络；DNS 则负责把域名解析成 IP 地址。简单来说就是：IP 负责定位设备，掩码负责判断是否同网段，网关负责跨网段通信，DNS 负责域名转 IP。

## 介绍一下DHCP协议

DHCP 是动态主机配置协议，主要作用是自动给客户端分配 IP 地址、子网掩码、默认网关、DNS 等网络参数。它基于 UDP，服务器使用 67 端口，客户端使用 68 端口。典型工作流程是 DORA，也就是 Discover、Offer、Request、ACK。客户端先广播寻找 DHCP 服务器，服务器提供一个可用 IP，客户端请求使用，最后服务器确认。DHCP 分配的 IP 一般还有租期，需要定期续租。

## 静态链接和动态链接

静态链接是在编译链接阶段把依赖库的代码直接合并到可执行文件中，所以生成的程序体积较大，但部署简单，运行时不依赖外部库。

动态链接则是在运行时加载 .so 或 .dll 等动态库，可执行文件更小，而且多个程序可以共享同一份库，但运行时依赖对应的动态库，可能存在库缺失或版本不兼容的问题。

一句话总结：

静态链接是“库代码直接打包进程序”，动态链接是“程序运行时再去加载库”。

## 什么情况下用vector，什么情况下用list

vector 是连续内存的动态数组，支持 O(1) 随机访问，遍历速度快、Cache 友好，适合读多、尾部插入多的场景。

list 是双向链表，不支持随机访问，但如果已经拿到目标位置的迭代器，在中间插入和删除可以做到 O(1)，适合频繁中间插入删除、又不需要随机访问的场景。

实际开发中一般优先使用 vector，只有确实需要链表特性时再使用 list。

## 中断函数能有返回值和参数吗

一般中断服务函数没有参数，也没有普通返回值，通常定义成 void ISR(void)。

因为 ISR 是硬件通过中断向量表直接进入的，不是普通函数调用，所以没有调用者给它传参数；中断结束时也是通过特殊的中断返回机制恢复现场，而不是把返回值交给某个调用者。

如果 ISR 需要向任务或主程序传递数据，一般通过全局变量、队列、信号量或者 RTOS 提供的 FromISR 接口来实现。

## 讲解一下什么是MQTT协议

MQTT 是一种基于 TCP 的轻量级发布/订阅消息协议，主要用于物联网和嵌入式场景。它包含 Publisher、Subscriber 和 Broker 三个角色，发布者把消息发布到 Topic，Broker 再转发给订阅了该 Topic 的客户端。MQTT 支持 QoS 0、1、2 三种可靠性等级，同时还支持 Keep Alive 心跳、遗嘱消息和保留消息。它协议开销小、设备之间耦合低，非常适合低带宽和网络不稳定的物联网环境。


## FreeRTOS的TCB控制块是什么
TCB 是 FreeRTOS 的任务控制块，每个任务都会对应一个 TCB。它主要保存任务的管理信息，比如任务优先级、任务状态、栈顶指针以及各种链表节点。

FreeRTOS 在进行任务调度和上下文切换时，会通过 TCB 找到任务的运行现场，所以 TCB 可以理解成操作系统管理任务的“身份证和档案”。

一句话总结：

TCB 是 FreeRTOS 描述一个任务的核心数据结构，调度器就是通过 TCB 来管理和切换各个任务的。

## 自旋锁和互斥锁的区别

自旋锁拿不到锁会一直循环等待，不让出 CPU，因此避免了线程切换开销，适合临界区非常短的场景；互斥锁拿不到锁会让线程阻塞并让出 CPU，等锁释放后再被唤醒，适合临界区较长或者竞争比较激烈的场景。

## FreeRTOS中的空闲任务

FreeRTOS 的空闲任务是调度器自动创建的最低优先级任务，主要作用是保证系统没有其他就绪任务时仍然有任务可以运行。另外，它还负责回收通过 vTaskDelete() 删除任务后留下的 TCB 和栈资源。

如果开启 Idle Hook，还可以在空闲任务中执行一些不阻塞的后台操作，比如低功耗处理。

## FreeRTOS中创建任务的方法和区别

FreeRTOS 创建任务最常见的有两种方式：xTaskCreate() 和 xTaskCreateStatic()。

xTaskCreate() 是动态创建，任务的 TCB 和栈空间由 FreeRTOS 从 Heap 中动态申请，使用方便，但存在动态内存申请失败和碎片问题。

xTaskCreateStatic() 是静态创建，需要用户提前提供 TCB 和任务栈空间，不依赖动态内存，所以内存使用更加确定，更适合可靠性要求高的嵌入式系统。

## TCP协议为什么会粘包，如何解决粘包问题
TCP 会出现粘包，是因为 TCP 是面向字节流的协议，没有消息边界，一次 send() 并不一定对应一次 recv()。多次发送的数据可能被一次接收，也可能一次发送的数据被分多次接收，所以会产生粘包和拆包现象。

解决方法是在应用层自己定义消息边界，常见方式有固定长度、特殊分隔符，以及最常用的“消息头中携带数据长度”。接收端通过缓存数据，根据协议不断解析出完整的数据包。

## 什么是虚函数

虚函数是 C++ 用来实现运行时多态的机制。在基类中用 virtual 修饰函数，子类可以重写它。当通过基类指针或引用调用虚函数时，会根据对象的实际类型决定调用哪个函数，而不是只看指针类型。底层通常通过虚函数表 vtable 和虚表指针 vptr 实现。它的核心作用就是实现动态绑定和多态。


## 使用C语言实现栈

```c
#include <stdio.h>

#define STACK_SIZE 100

typedef struct
{
    int data[STACK_SIZE];
    int top;
} Stack;

/* 初始化栈 */
void StackInit(Stack *s)
{
    s->top = -1;
}

/* 判断栈是否为空 */
int StackIsEmpty(Stack *s)
{
    return s->top == -1;
}

/* 判断栈是否已满 */
int StackIsFull(Stack *s)
{
    return s->top == STACK_SIZE - 1;
}

/* 入栈 */
int StackPush(Stack *s, int value)
{
    if (StackIsFull(s))
    {
        return -1;
    }

    s->data[++s->top] = value;
    return 0;
}

/* 出栈 */
int StackPop(Stack *s, int *value)
{
    if (StackIsEmpty(s))
    {
        return -1;
    }

    *value = s->data[s->top--];
    return 0;
}

/* 获取栈顶元素 */
int StackTop(Stack *s, int *value)
{
    if (StackIsEmpty(s))
    {
        return -1;
    }

    *value = s->data[s->top];
    return 0;
}

int main(void)
{
    Stack s;
    int value;

    StackInit(&s);

    StackPush(&s, 10);
    StackPush(&s, 20);
    StackPush(&s, 30);

    StackTop(&s, &value);
    printf("栈顶元素: %d\n", value);

    while (!StackIsEmpty(&s))
    {
        StackPop(&s, &value);
        printf("出栈: %d\n", value);
    }

    return 0;
}
```
## 当for循环遇到fork函数

当 `for` 循环中执行到 `fork()` 时，当前进程会创建一个子进程。子进程会复制父进程当前的执行状态，并从 `fork()` 返回的位置继续往下执行。

所以如果父进程和子进程都继续参与后面的循环，那么每执行一次 `fork()`，进程数量通常会翻倍。

例如循环执行 3 次：

```c
for (int i = 0; i < 3; i++) {
    fork();
}
```

初始有 1 个进程，三次之后进程数就是：

1 → 2 → 4 → 8

也就是最终有 `2^3 = 8` 个进程。

不过实际题目不能直接套 `2^n`，还要看 `fork()` 的返回值判断、`break`、`exit`、`wait` 等逻辑，因为这些都会影响哪些进程继续执行循环。


## 深拷贝和浅拷贝的区别

浅拷贝只是按成员复制，如果对象里有指针，复制的是地址，所以两个对象会指向同一块内存，容易出现相互影响和重复释放。深拷贝会重新申请内存，再把原数据复制过去，因此两个对象资源独立。C++ 中如果类管理动态内存，通常需要自己实现拷贝构造和拷贝赋值。

## 什么是函数重载

函数重载就是：同一个作用域里，函数名相同，但参数列表不同，编译器会根据实参自动选择对应函数。

```
#include <iostream>
using namespace std;

int add(int a, int b)
{
    return a + b;
}

double add(double a, double b)
{
    return a + b;
}

int main()
{
    cout << add(1, 2) << endl;       // 调用 int 版本
    cout << add(1.2, 2.3) << endl;   // 调用 double 版本
}
```

函数重载是 C++ 的静态多态。多个函数可以同名，只要参数个数、类型或顺序不同，编译器会在编译阶段根据实参匹配对应函数。仅返回值不同不能构成重载。


## fork和vfork的区别

fork 和 vfork 都能创建子进程。fork 创建后父子进程拥有独立地址空间，Linux 一般用写时复制优化；而 vfork 创建后子进程会暂时共享父进程地址空间，并阻塞父进程，直到子进程执行 exec 或 _exit。所以 vfork 主要适合子进程创建后马上执行 exec 的场景，而且子进程不能随便修改变量或从当前函数正常 return。


## 面向对象的三大特征

- 封装：把数据和操作数据的方法封装到类中，通过 private/public 控制访问权限。
- 继承：子类可以继承父类的属性和方法，实现代码复用。
- 多态：同一个接口可以表现出不同的行为，比如父类指针指向不同子类对象时，调用虚函数会执行对应子类的方法。

## select、poll、 epoll

select、poll、epoll 都用于 I/O 多路复用。select 有最大 fd 数量限制，并且每次调用都要把整个 fd 集合从用户态拷贝到内核态，还要线性遍历；poll 取消了固定数量限制，但本质上仍然需要遍历所有 fd；epoll 使用事件驱动机制，内核只返回已经就绪的 fd，因此在大量连接场景下效率更高，常用于高并发服务器。

| 对比        | select            | poll  | epoll    |
| --------- | ----------------- | ----- | -------- |
| fd 数量限制   | 有，通常 `FD_SETSIZE` | 无固定限制 | 无固定限制    |
| 查找就绪 fd   | 线性遍历              | 线性遍历  | 只返回就绪 fd |
| 每次传递全部 fd | 是                 | 是     | 否，注册一次   |
| 高并发性能     | 较差                | 一般    | 最好       |
| Linux 特有  | 否                 | 否     | 是        |

## memcpy和strcpy的区别

memcpy 和 strcpy 的主要区别是：memcpy 按指定字节数复制内存，strcpy 专门复制 C 字符串，直到遇到 \0 为止。
~~~
#include <string.h>

char src[] = "hello";
char dst1[20];
char dst2[20];

strcpy(dst1, src);                  // 复制到 '\0' 为止
memcpy(dst2, src, strlen(src) + 1); // 按字节数复制
~~~

## FreeRTOS中队列和信号量的区别


FreeRTOS 的队列 Queue 可以在任务之间传递实际数据，发送时会把数据复制到队列中；信号量 Semaphore 一般不传递具体数据，主要用于任务同步、事件通知或者互斥访问共享资源。二值信号量适合事件同步，计数信号量适合资源计数，互斥信号量用于保护临界资源，并且支持优先级继承。
