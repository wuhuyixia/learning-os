# Linux 进程上下文切换：CPU 是怎么从 P1 切到 P2 的？

CPU 在某一时刻只能执行当前被调度进程的指令。当系统里有多个可运行进程时，操作系统需要不断在它们之间切换，这就是 **上下文切换（Context Switch）**。

最简单的理解是：

> **先保存当前进程的 CPU 执行现场，再恢复下一个进程之前保存的现场。**

这个“现场”主要包括通用寄存器、程序计数器 PC、栈指针 SP 和状态寄存器等。PC 尤其重要，因为它决定进程恢复后从哪条指令继续。

```text
P1 执行
  ↓
保存 P1 上下文
  ↓
调度器选择 P2

恢复 P2 上下文
  ↓
P2 执行
  ↓
再次切换
  ↓
恢复 P1
```

## 1. 什么叫进程上下文？

假设 P1 正在执行：

```asm
LOAD R0, 12
LOAD R1, 20
ADD  R0, R1
STORE R0, [0x1100]
```

执行到第三条之后，CPU 里可能是：

```text
R0 = 32
R1 = 20
PC = 0x1003
SP = 0x7FF0
```

这些值描述了 P1 当前执行到哪里、寄存器是什么状态。切走之前如果不保存，之后就无法正确恢复。

## 2. 上下文保存在哪里？

教学上通常会说上下文保存在 PCB 中。Linux 中进程的核心描述结构是 `task_struct`，但真实内核不会简单地把所有寄存器按顺序塞进一个固定数组。

可以概念化理解为：

```text
task_struct / 进程控制信息
├─ 进程状态
├─ 调度信息
├─ 内存信息
├─ 文件资源
└─ 与执行上下文相关的数据
   ├─ PC
   ├─ SP
   ├─ 通用寄存器
   └─ 状态寄存器
```

实际保存位置会涉及任务结构、内核栈以及体系结构相关的数据结构。

## 3. 为什么切回来还能继续？

因为 PC 被保存了。

如果 P1 切走时：

```text
R0 = 32
R1 = 20
PC = 0x1003
SP = 0x7FF0
```

以后恢复 P1 时，操作系统会重新装回这些状态：

```text
CPU.R0 <- 32
CPU.R1 <- 20
CPU.PC <- 0x1003
CPU.SP <- 0x7FF0
```

于是下一条继续执行：

```asm
STORE R0, [0x1100]
```

而不是从第一条指令重新开始。

所以进程切换不是“重启程序”，而是**暂停后继续**。

## 4. 一次上下文切换的主流程

可以把 P1 → P2 简化成：

```text
P1 RUNNING
    ↓
时钟中断 / 阻塞 / 调度点
    ↓
进入内核
    ↓
保存 P1 上下文
    ↓
调度器选择 P2
    ↓
恢复 P2 上下文
    ↓
P2 RUNNING
```

这里有两个相关但不同的动作：

```text
调度：决定“下一个运行谁”
切换：完成“CPU 状态从旧任务变成新任务”
```

## 5. 什么情况下会触发切换？

常见场景包括：

- 时间片耗尽；
- 进程等待 I/O；
- 进程主动 sleep；
- 等待锁或其他资源；
- 更高优先级任务被唤醒；
- 当前进程退出。

例如：

```c
read(fd, buf, 100);
```

如果数据还没准备好，当前进程可能阻塞。操作系统就可以把 CPU 交给其他就绪进程。

## 6. 为什么上下文切换有开销？

上下文切换不是免费的。系统要保存和恢复寄存器、运行调度逻辑；不同进程切换时还可能切换地址空间相关状态，并影响 TLB、CPU Cache、分支预测和内存局部性。

因此：

> **任务越多不代表一定越快，过于频繁的切换反而会消耗 CPU 时间。**

## 7. 进程切换和线程切换有什么区别？

同一进程中的线程通常共享代码段、数据段、堆、虚拟地址空间和打开的文件，但线程仍各自拥有自己的 PC、SP、寄存器和线程栈。

因此线程切换同样需要保存/恢复 CPU 上下文，只是同一进程内线程切换通常不需要更换完整地址空间，所以一般比不同进程之间切换更轻。

## 8. 和 FreeRTOS 任务切换有什么关系？

如果学过 FreeRTOS，这个过程会很熟悉。

Cortex-M 上的 FreeRTOS 任务切换同样需要保存当前任务寄存器现场，再恢复另一个任务的现场，PendSV 常被用于完成这一步。

核心思想完全一致：

```text
Save
  ↓
Schedule
  ↓
Restore
```

区别主要在于 Linux 还要处理虚拟内存、用户态/内核态、进程资源等更复杂的内容。

## 9. 一句话记住

上下文切换本质就是：

```text
当前进程寄存器
      ↓ 保存
操作系统
      ↓ 调度
下一个进程上下文
      ↓ 恢复
CPU 寄存器
      ↓
继续执行
```

只要理解了 **PC、SP、寄存器、进程控制信息和调度器**，就能理解为什么多个进程在单核 CPU 上看起来像是在“同时运行”。
