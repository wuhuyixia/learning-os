# Linux 基础入门-进程间通信

学习 IPC 之前，先要搞清楚一个问题：**为什么进程之间需要“通信”，而线程之间却经常可以直接读写同一个变量？**

答案就在进程与线程的资源关系里。

## 1. 进程和线程的区别与联系

可以把**进程**想象成一个“独立的房间”，把**线程**想象成这个房间里的“多个工人”。

一个进程拥有自己独立的虚拟地址空间、代码、全局数据、堆、打开的文件等资源；而同一个进程里的多个线程会共享这些进程资源，但每个线程又有自己独立的栈、寄存器和程序计数器等执行现场。

| 对比 | 进程 Process | 线程 Thread |
| :--- | :--- | :--- |
| 地址空间 | 相互独立 | 同一进程内共享 |
| 全局变量、堆 | 不直接共享 | 同一进程内共享 |
| 栈 | 每个进程自己的线程各自拥有 | 每个线程独立 |
| 创建/切换开销 | 较大 | 较小 |
| 隔离性 | 强 | 弱 |
| 通信方式 | 需要 IPC | 可直接访问共享变量，但要同步 |

例如：

```c
#include <pthread.h>
#include <stdio.h>

int g_value = 100;   // 同一进程内的线程共享

void *worker(void *arg)
{
    g_value++;
    return NULL;
}

int main(void)
{
    pthread_t tid;
    pthread_create(&tid, NULL, worker, NULL);
    pthread_join(tid, NULL);

    printf("g_value = %d\n", g_value);
    return 0;
}
```

上面的 `g_value` 可以被主线程和工作线程共同访问，因为它们属于同一个进程。

但两个独立进程就不同：

```c
#include <stdio.h>
#include <unistd.h>
#include <sys/wait.h>

int g_value = 100;

int main(void)
{
    pid_t pid = fork();

    if (pid == 0) {
        g_value = 200;
        printf("child: %d\n", g_value);
    } else {
        wait(NULL);
        printf("parent: %d\n", g_value);
    }

    return 0;
}
```

虽然 `fork()` 之后父子进程一开始看到的内容相同，但它们拥有各自独立的地址空间，子进程把 `g_value` 改成 200，并不会让父进程里的 `g_value` 也变成 200。

这个图最关键的不是死记地址，而是看懂“**谁共享、谁独立**”：

- `.text`、`.data`、`.bss`、Heap 属于进程级资源，同一进程内的线程共享；
- 每个线程都有独立 Stack，用来保存自己的局部变量、函数调用现场等；
- 不同进程拥有不同的虚拟地址空间，所以进程 A 和进程 B 的 `.data`、`.bss`、Heap 并不是同一份；
- 内核空间位于用户空间之上，用户进程不能像访问普通用户变量一样随意直接访问内核地址。

你第二张图里几类变量，可以这样对应：

```c
int globalVar = 10;             // 已初始化全局变量 -> .data
static int staticGlobal = 20;   // 已初始化 static -> .data
int globalUninit;               // 未初始化全局变量 -> .bss
static int staticUninit;        // 未初始化 static -> .bss

void showKeyword(void)
{
    static int staticVar = 30;  // 静态存储期，通常仍在 .data
    int autoVar = 40;           // 普通局部变量 -> 当前线程 Stack
    register int regVar = 50;   // register 只是提示，是否进寄存器由编译器决定
    int *p = malloc(sizeof(int));
    // p 本身是局部变量，通常在 Stack；malloc 得到的对象在 Heap
}
```

需要特别注意两点。第一，图片里“每个进程都有 4 GB 虚拟内存，3 GB 用户空间 + 1 GB 内核空间”是**典型 32 位 Linux 教学模型**，不应直接推广到所有 Linux 系统；64 位 Linux 的地址空间远大于 4 GB，而且具体内核/用户区划分与架构和内核配置有关。第二，`register` 不等于“变量一定在 CPU 寄存器里”，现代编译器通常自己决定是否分配寄存器。

一句话记忆：

> **线程是“共享多、隔离弱”，进程是“共享少、隔离强”。线程之间容易通信，但要小心并发；进程之间更安全，但需要 IPC。**

## 2. 为什么进程之间需要 IPC

Linux 中不同进程拥有彼此独立的虚拟地址空间。即使两个进程打印出的虚拟地址一样，也不代表它们访问的是同一块物理内存。

```text
Process A                    Process B

0x1000 -> value = 100        0x1000 -> value = 200
      \                         /
       \                       /
        -> 不同的物理页 <-
```

因此：

```text
A 修改自己的 value
        ↓
不会直接影响
        ↓
B 的 value
```

IPC（Inter-Process Communication，进程间通信）就是操作系统提供的一组机制，让这些相互隔离的进程能够交换数据、发送通知和完成同步。

可以先记一句：

> **IPC 的本质，就是给两个隔离的进程搭一座桥。**

## 3. Linux 常见进程间通信方式

你截图里列出的内容，可以归纳成这几类：

```text
进程间通信
├─ 无名管道 Pipe
├─ 有名管道 FIFO
├─ 信号 Signal
├─ 共享内存 Shared Memory
├─ 消息队列 Message Queue
├─ 信号量 Semaphore
└─ Socket
```

另外，**动态库编译本身不属于 IPC**，但它经常和 Linux 进程开发一起学习，因为不同进程都可能装载同一个 `.so` 动态库的代码段。

## 4. 无名管道 Pipe

无名管道是最基础的 IPC 方式之一。它可以理解成：**内核里放了一根水管，进程从一头写，另一个进程从另一头读。**

```text
父进程/子进程
     write()
        ↓
   内核 Pipe Buffer
        ↓
      read()
父进程/子进程
```

### 4.1 `pipe()` 函数

你截图里的函数原型是：

```c
#include <unistd.h>

int pipe(int fd[2]);
```

其中：

```text
fd[0] -> 读端
fd[1] -> 写端
```

返回值：

```text
成功：0
失败：-1
```

最简单的创建方法：

```c
int pipefd[2];

if (pipe(pipefd) == -1) {
    perror("pipe");
    return 1;
}
```

### 4.2 为什么 Pipe 经常和 `fork()` 一起用

关键点在于：**父进程先创建 Pipe，再 `fork()`，子进程会继承父进程已经打开的文件描述符。**

这就对应你截图里的结构：父进程和子进程都有 `fd[0]`、`fd[1]`，但它们指向的是内核中的同一个管道对象。

/>

### 4.3 完整示例：子进程写，父进程读

```c
#include <stdio.h>
#include <string.h>
#include <unistd.h>
#include <sys/wait.h>

int main(void)
{
    int pipefd[2];
    char buf[64] = {0};

    if (pipe(pipefd) == -1) {
        perror("pipe");
        return 1;
    }

    pid_t pid = fork();

    if (pid < 0) {
        perror("fork");
        return 1;
    }

    if (pid == 0) {
        /* 子进程只负责写，所以关闭读端 */
        close(pipefd[0]);

        const char *msg = "Hello, I am son!";
        write(pipefd[1], msg, strlen(msg) + 1);

        close(pipefd[1]);
        return 0;
    }

    /* 父进程只负责读，所以关闭写端 */
    close(pipefd[1]);

    read(pipefd[0], buf, sizeof(buf));
    printf("parent recv: %s\n", buf);

    close(pipefd[0]);
    wait(NULL);
    return 0;
}
```

这里最容易问的是：**为什么一定要关闭不用的那一端？**

因为如果父进程自己还保留着写端，那么即使子进程已经关闭写端，内核仍然认为“还有写端存在”，某些情况下父进程的 `read()` 就无法正确感知 EOF。

### 4.4 无名管道的特点

- 本质是内核缓冲区；
- 默认是半双工字节流；
- 没有普通文件名；
- 典型用于有亲缘关系的进程；
- 数据读走后就没了，不是普通磁盘文件。

## 5. 有名管道 FIFO

无名管道最大的限制是：两个毫无关系的进程不方便事先拿到同一个 `fd`。

于是 Linux 提供了 FIFO，也叫**命名管道**。

它的特点是：

> **通信方式仍然像管道，但在文件系统里有一个名字。**

### 5.1 `mkfifo()` 函数

你截图中的函数原型可以写成：

```c
#include <sys/types.h>
#include <sys/stat.h>

int mkfifo(const char *pathname, mode_t mode);
```

例如：

```c
if (mkfifo("/tmp/myfifo", 0666) == -1) {
    perror("mkfifo");
}
```

其中：

```text
pathname -> FIFO 路径
mode     -> 权限，例如 0666
成功     -> 0
失败     -> -1
```

也可以直接用 Shell：

```bash
mkfifo /tmp/myfifo
```

然后两个终端就可以通信。

终端 A：

```bash
echo "hello fifo" > /tmp/myfifo
```

终端 B：

```bash
cat /tmp/myfifo
```

    F -->|read| B[Process B]
    C[文件系统中有名字] -.-> F

### 5.2 Pipe 和 FIFO 的区别

| 对比 | Pipe | FIFO |
| :--- | :--- | :--- |
| 是否有名字 | 没有 | 有 pathname |
| 是否出现在文件系统 | 不作为普通路径使用 | 会看到一个特殊文件节点 |
| 常见通信双方 | 父子进程 | 任意两个进程 |
| 数据是否长期存盘 | 否 | 否 |

一句话：

> **Pipe 是“匿名水管”，FIFO 是“有门牌号的水管”。**

## 6. 信号 Signal

Signal 主要做的是**通知**，而不是搬运大块数据。

例如：

```text
SIGINT   Ctrl+C
SIGTERM  请求进程退出
SIGKILL  强制终止
SIGCHLD  子进程状态发生变化
SIGALRM  定时器到期
```

使用 `kill()` 给另一个进程发送信号：

```c
kill(pid, SIGTERM);
```

接收端可以用 `sigaction()` 注册处理函数：

```c
#include <signal.h>
#include <stdio.h>
#include <unistd.h>

static void handler(int sig)
{
    write(STDOUT_FILENO, "signal arrived\n", 15);
}

int main(void)
{
    struct sigaction sa = {0};
    sa.sa_handler = handler;
    sigemptyset(&sa.sa_mask);
    sigaction(SIGINT, &sa, NULL);

    while (1)
        pause();
}
```

信号适合做：

```text
“有事发生了，你处理一下”
```

不适合做：

```text
“我给你传 10 MB 数据”
```

## 7. 共享内存 Shared Memory

共享内存是最容易理解“为什么快”的 IPC。

普通 Pipe 往往需要在用户空间和内核之间复制数据，而共享内存则是让两个进程把**同一块物理内存映射到各自地址空间**。

```text
Process A VA ----\
                  >---- 同一块物理内存
Process B VA ----/
```

POSIX 方式常见接口：

```c
shm_open();
ftruncate();
mmap();
munmap();
shm_unlink();
```

共享内存虽然快，但它只解决“数据放在哪里”，不自动解决“谁先访问”。所以通常还需要搭配信号量或进程间互斥锁。

## 8. 消息队列 Message Queue

消息队列适合一条一条发送结构化消息，它和 Pipe 最大的区别之一是**保留消息边界**。

```text
Pipe:
[helloabc123xyz...]

Message Queue:
[msg 1: hello]
[msg 2: abc]
[msg 3: 123]
```

System V 常见接口：

```c
msgget();
msgsnd();
msgrcv();
msgctl();
```

例如：

```c
struct msgbuf {
    long mtype;
    char mtext[128];
};
```

如果应用层本身就是“命令 1、命令 2、事件 3”这种消息模型，消息队列通常比自己在 Pipe 字节流里切包更直观。

## 9. 信号量 Semaphore

信号量主要做同步，而不是传大块数据。

```text
count > 0 -> 可以获取资源
count = 0 -> 等待
```

最常见理解：

```text
P / wait / down -> 获取，计数减 1
V / post / up   -> 释放，计数加 1
```

和共享内存搭配时可以理解成：

```text
Process A 写共享内存
        ↓
post semaphore
        ↓
Process B 被唤醒
        ↓
读取共享内存
```

所以：

> **共享内存负责“放数据”，信号量负责“排顺序”。**

## 10. Socket

Socket 既可以用于本机 IPC，也可以跨主机通信。

```text
TCP Socket
UDP Socket
Unix Domain Socket
```

如果双方只在同一台 Linux 主机上，Unix Domain Socket 是非常常见的选择；如果跨网络，则通常使用 TCP/UDP Socket。

## 11. 为什么共享内存通常更快

如果 Process A 要把一大块数据交给 Process B，Pipe 可以简化理解为：

```text
A 用户空间
   ↓ copy
内核缓冲区
   ↓ copy
B 用户空间
```

共享内存则更像：

```text
Process A VA ----\
                  >---- Same Physical Memory
Process B VA ----/
```

建立映射时需要内核参与，但之后双方可以直接访问同一片共享物理内存，因此非常适合大数据量、高频通信。

代价是程序员需要自己处理：

- 同步；
- 互斥；
- 数据一致性；
- 生命周期。

## 12. Pipe、FIFO、消息队列怎么区分

| 对比 | Pipe | FIFO | Message Queue |
| :--- | :--- | :--- | :--- |
| 数据模型 | 字节流 | 字节流 | 一条条消息 |
| 是否有文件名 | 否 | 是 | 不是普通文件 |
| 常见关系 | 父子进程 | 任意进程 | 任意进程 |
| 消息边界 | 无 | 无 | 有 |

一句话：

> **Pipe 是匿名水管，FIFO 是有门牌号的水管，Message Queue 是一个装信封的邮箱。**

## 13. 动态库编译和 IPC 是什么关系

你截图里还列了“信号量和动态库编译”。这里需要区分：**动态库本身不是 IPC。**

动态库 `.so` 是 Linux 程序复用代码的一种方式。多个进程可以装载同一个动态库，其只读代码页在物理内存层面可能被系统共享，但每个进程依然拥有自己的进程地址空间和可写数据状态。

例如：

```c
// add.c
int add(int a, int b)
{
    return a + b;
}
```

编译动态库：

```bash
gcc -fPIC -c add.c -o add.o
gcc -shared add.o -o libadd.so
```

程序链接：

```bash
gcc main.c -L. -ladd -o app
```

运行时如果系统找不到 `.so`，可以临时设置：

```bash
export LD_LIBRARY_PATH=$PWD:$LD_LIBRARY_PATH
```

所以：

```text
IPC       -> 解决进程之间如何通信
动态库 .so -> 解决代码如何复用和动态装载
```

## 16. 总结

Linux IPC 可以按下面这条线记：

```text
Pipe
  -> 有亲缘关系进程的匿名字节流

FIFO
  -> 有名字的字节流管道

Signal
  -> 异步通知

Shared Memory
  -> 共享同一块物理内存，高速传大数据

Message Queue
  -> 一条条消息，有边界

Semaphore
  -> 同步和资源计数

Socket
  -> 本机或跨主机通信
```

面试中如果被问到“Linux 进程间通信有哪些方式”，可以直接回答：

> Linux 常见的 IPC 包括匿名管道、命名管道、信号、共享内存、消息队列、信号量和 Socket。Pipe 适合父子进程，FIFO 可以用于无亲缘关系进程；共享内存传大块数据效率高，但通常需要配合信号量或互斥锁同步；信号主要做异步通知，消息队列保留消息边界，Socket 则既可以本机通信，也可以跨主机通信。
