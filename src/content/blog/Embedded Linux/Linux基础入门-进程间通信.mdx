# Linux 基础入门-进程间通信

学习 IPC 之前，先要搞清楚一个问题：**为什么进程之间需要“通信”，而线程之间却经常可以直接读写同一个变量？**

答案就在进程与线程的资源关系里。

## 1. 进程和线程的区别与联系

可以把**进程**想象成一个“独立的房间”，把**线程**想象成这个房间里的“多个工人”。

一个进程拥有自己独立的虚拟地址空间、代码、全局数据、堆、打开的文件等资源；而同一个进程里的多个线程会共享这些进程资源，但每个线程又有自己独立的栈、寄存器和程序计数器等执行现场。

| 对比 | 进程 Process | 线程 Thread |
| :--- | :--- | :--- |
| 地址空间 | 相互独立 | 同一进程内共享 |
| 全局变量、堆 | 不直接共享 | 同一进程内共享 |
| 栈 | 每个进程自己的线程各自拥有 | 每个线程独立 |
| 创建/切换开销 | 较大 | 较小 |
| 隔离性 | 强 | 弱 |
| 通信方式 | 需要 IPC | 可直接访问共享变量，但要同步 |

例如：

```c
#include <pthread.h>
#include <stdio.h>

int g_value = 100;   // 同一进程内的线程共享

void *worker(void *arg)
{
    g_value++;
    return NULL;
}

int main(void)
{
    pthread_t tid;
    pthread_create(&tid, NULL, worker, NULL);
    pthread_join(tid, NULL);

    printf("g_value = %d\n", g_value);
    return 0;
}
```

上面的 `g_value` 可以被主线程和工作线程共同访问，因为它们属于同一个进程。

但两个独立进程就不同：

```c
#include <stdio.h>
#include <unistd.h>
#include <sys/wait.h>

int g_value = 100;

int main(void)
{
    pid_t pid = fork();

    if (pid == 0) {
        g_value = 200;
        printf("child: %d\n", g_value);
    } else {
        wait(NULL);
        printf("parent: %d\n", g_value);
    }

    return 0;
}
```

虽然 `fork()` 之后父子进程一开始看到的内容相同，但它们拥有各自独立的地址空间，子进程把 `g_value` 改成 200，并不会让父进程里的 `g_value` 也变成 200。

一句话记忆：

> **线程是“共享多、隔离弱”，进程是“共享少、隔离强”。线程之间容易通信，但要小心并发；进程之间更安全，但需要 IPC。**

## 2. 为什么进程之间需要 IPC

Linux 中不同进程拥有彼此独立的虚拟地址空间。即使两个进程打印出的虚拟地址一样，也不代表它们访问的是同一块物理内存。

```text
Process A                    Process B

0x1000 -> value = 100        0x1000 -> value = 200
      \                         /
       \                       /
        -> 不同的物理页 <-
```

因此：

```text
A 修改自己的 value
        ↓
不会直接影响
        ↓
B 的 value
```

IPC（Inter-Process Communication，进程间通信）就是操作系统提供的一组机制，让这些相互隔离的进程能够交换数据、发送通知和完成同步。

可以先记一句：

> **IPC 的本质，就是给两个隔离的进程搭一座桥。**

你截图里列出的内容，可以归纳成这几类：

## 4. 无名管道 Pipe

无名管道是最基础的 IPC 方式之一。它可以理解成：**内核里放了一根水管，进程从一头写，另一个进程从另一头读。**

```text
父进程/子进程
     write()
        ↓
   内核 Pipe Buffer
        ↓
      read()
父进程/子进程
```

### 4.1 `pipe()` 函数

你截图里的函数原型是：

```c
#include <unistd.h>

int pipe(int fd[2]);
```

其中：

```text
fd[0] -> 读端
fd[1] -> 写端
```

返回值：

```text
成功：0
失败：-1
```

最简单的创建方法：

```c
int pipefd[2];

if (pipe(pipefd) == -1) {
    perror("pipe");
    return 1;
}
```

### 4.2 为什么 Pipe 经常和 `fork()` 一起用

关键点在于：**父进程先创建 Pipe，再 `fork()`，子进程会继承父进程已经打开的文件描述符。**

这就对应你截图里的结构：父进程和子进程都有 `fd[0]`、`fd[1]`，但它们指向的是内核中的同一个管道对象。

  chart={`sequenceDiagram

    participant K as 内核 Pipe

    P->>C: fork()

    C->>K: close(fd[0])
    C->>K: write(fd[1], data)
    P->>K: close(fd[1])
    K-->>P: read(fd[0], buf)`}
/>

### 4.3 完整示例：子进程写，父进程读

```c
#include <stdio.h>
#include <string.h>
#include <unistd.h>
#include <sys/wait.h>

int main(void)
{
    int pipefd[2];
    char buf[64] = {0};

    if (pipe(pipefd) == -1) {
        perror("pipe");
        return 1;
    }

    pid_t pid = fork();

    if (pid < 0) {
        perror("fork");
        return 1;
    }

    if (pid == 0) {
        /* 子进程只负责写，所以关闭读端 */
        close(pipefd[0]);

        const char *msg = "Hello, I am son!";
        write(pipefd[1], msg, strlen(msg) + 1);

        close(pipefd[1]);
        return 0;
    }

    /* 父进程只负责读，所以关闭写端 */
    close(pipefd[1]);

    read(pipefd[0], buf, sizeof(buf));
    printf("parent recv: %s\n", buf);

    close(pipefd[0]);
    wait(NULL);
    return 0;
}
```

这里最容易问的是：**为什么一定要关闭不用的那一端？**

因为如果父进程自己还保留着写端，那么即使子进程已经关闭写端，内核仍然认为“还有写端存在”，某些情况下父进程的 `read()` 就无法正确感知 EOF。

### 4.4 无名管道的特点

- 本质是内核缓冲区；
- 默认是半双工字节流；
- 没有普通文件名；
- 典型用于有亲缘关系的进程；
- 数据读走后就没了，不是普通磁盘文件。

## 5. 有名管道 FIFO

无名管道最大的限制是：两个毫无关系的进程不方便事先拿到同一个 `fd`。

于是 Linux 提供了 FIFO，也叫**命名管道**。

它的特点是：

> **通信方式仍然像管道，但在文件系统里有一个名字。**

### 5.1 `mkfifo()` 函数

你截图中的函数原型可以写成：

```c
#include <sys/types.h>
#include <sys/stat.h>

int mkfifo(const char *pathname, mode_t mode);
```

例如：

```c
if (mkfifo("/tmp/myfifo", 0666) == -1) {
    perror("mkfifo");
}
```

其中：

```text
pathname -> FIFO 路径
mode     -> 权限，例如 0666
成功     -> 0
失败     -> -1
```

也可以直接用 Shell：

```bash
mkfifo /tmp/myfifo
```

然后两个终端就可以通信。

终端 A：

```bash
echo "hello fifo" > /tmp/myfifo
```

终端 B：

```bash
cat /tmp/myfifo
```

<MermaidDiagram
  title="FIFO：两个无亲缘关系进程通信"
  chart={`flowchart LR
    A[Process A] -->|write| F[/tmp/myfifo\nFIFO]
    F -->|read| B[Process B]
    C[文件系统中有名字] -.-> F
    F -. 数据实际仍通过内核管道机制 .-> K[Kernel]`}
/>

### 5.2 Pipe 和 FIFO 的区别

| 对比 | Pipe | FIFO |
| :--- | :--- | :--- |
| 是否有名字 | 没有 | 有 pathname |
| 是否出现在文件系统 | 不作为普通路径使用 | 会看到一个特殊文件节点 |
| 常见通信双方 | 父子进程 | 任意两个进程 |
| 数据是否长期存盘 | 否 | 否 |

一句话：

> **Pipe 是“匿名水管”，FIFO 是“有门牌号的水管”。**

## 6. 信号 Signal

Signal 主要做的是**通知**，而不是搬运大块数据。

例如：

```text
SIGINT   Ctrl+C
SIGTERM  请求进程退出
SIGKILL  强制终止
SIGCHLD  子进程状态发生变化
SIGALRM  定时器到期
```

使用 `kill()` 给另一个进程发送信号：

```c
kill(pid, SIGTERM);
```

接收端可以用 `sigaction()` 注册处理函数：

```c
#include <signal.h>
#include <stdio.h>
#include <unistd.h>

static void handler(int sig)
{
    write(STDOUT_FILENO, "signal arrived\n", 15);
}

int main(void)
{
    struct sigaction sa = {0};
    sa.sa_handler = handler;
    sigemptyset(&sa.sa_mask);
    sigaction(SIGINT, &sa, NULL);

    while (1)
        pause();
}
```

信号适合做：

```text
“有事发生了，你处理一下”
```

不适合做：

```text
“我给你传 10 MB 数据”
```

## 7. 共享内存 Shared Memory

共享内存是最容易理解“为什么快”的 IPC。

普通 Pipe 往往需要在用户空间和内核之间复制数据，而共享内存则是让两个进程把**同一块物理内存映射到各自地址空间**。

```text
Process A VA ----\
                  >---- 同一块物理内存
Process B VA ----/
```

POSIX 方式常见接口：

```c
shm_open();
ftruncate();
mmap();
munmap();
shm_unlink();
```

简单示意：

```c
int fd = shm_open("/demo_shm", O_CREAT | O_RDWR, 0666);
ftruncate(fd, 4096);

char *p = mmap(NULL, 4096,
               PROT_READ | PROT_WRITE,
               MAP_SHARED,
               fd, 0);
```

映射完成后，不同进程只要映射的是同一个共享内存对象，就可以看到同一块数据。

但共享内存有一个很重要的问题：

> **它只解决“大家都能看到”，不解决“谁先写、谁后读”。**

所以一般需要配合信号量或互斥锁。

## 8. 消息队列 Message Queue

消息队列可以理解成内核中的“邮箱”。

Pipe 更像连续水流：

```text
[helloabc123xyz...]
```

消息队列则是一封一封信：

```text
[msg1: hello]
[msg2: abc]
[msg3: 123]
```

System V 消息队列常见接口：

```c
msgget();
msgsnd();
msgrcv();
msgctl();
```

消息结构一般带消息类型：

```c
struct msgbuf {
    long mtype;
    char mtext[128];
};
```

因此消息队列很适合命令、事件、任务这种“一条一条处理”的数据。

## 9. 信号量 Semaphore

信号量主要负责**同步**，它本身并不负责搬运大数据。

可以把它想成停车场剩余车位：

```text
count > 0 -> 还有资源，可以进入
count = 0 -> 没资源，等待
```

经典操作：

```text
P / wait / down -> 获取资源，计数减 1
V / post / up   -> 释放资源，计数加 1
```

共享内存和信号量经常组合：

一句话：

> **共享内存负责“传数据”，信号量负责“排队和协调”。**

## 10. Socket

Socket 可以用于本机进程通信，也可以跨主机通信。

常见类型：

```text
TCP Socket
UDP Socket
Unix Domain Socket
```

TCP Socket 基本流程：

## 11. 动态库编译：为什么它不属于 IPC

你截图里把“信号量和动态库编译”放在一起，但从概念上要分清：

```text
信号量 -> IPC / 同步机制
动态库 -> 程序链接与代码复用机制
```

一个简单动态库：

```c
// add.c
int add(int a, int b)
{
    return a + b;
}
```

编译成 `.so`：

```bash
gcc -fPIC -c add.c -o add.o
gcc -shared add.o -o libadd.so
```

主程序：

```c
#include <stdio.h>

extern int add(int a, int b);

int main(void)
{
    printf("%d\n", add(1, 2));
    return 0;
}
```

链接：

```bash
gcc main.c -L. -ladd -o app
```

运行时如果系统找不到动态库，可以临时设置：

```bash
export LD_LIBRARY_PATH=$PWD:$LD_LIBRARY_PATH
./app
```

动态库解决的是“多个程序复用同一份库代码”，并不是让两个正在运行的进程互相传消息。

## 12. 共享内存为什么通常最快

假设 Process A 要传 1 MB 数据给 Process B。

Pipe 的概念路径：

```text
A 用户空间
    ↓ copy
内核缓冲区
    ↓ copy
B 用户空间
```

共享内存：

```text
A 虚拟地址 ----\
                 -> 同一块物理内存
B 虚拟地址 ----/
```

因此对于大块、高频数据，共享内存通常更高效。

但它也把更多责任交给程序员：

- 谁先写；
- 谁后读；
- 多个进程同时修改怎么办；
- 数据什么时候有效；
- 共享区什么时候销毁。

所以共享内存常和信号量、互斥锁配合使用。

## 13. 常见 IPC 怎么选

| 需求 | 推荐方式 |
| :--- | :--- |
| 父子进程简单传字节流 | Pipe |
| 无亲缘关系进程传字节流 | FIFO |
| 发送异步通知 | Signal |
| 大量高速数据 | Shared Memory |
| 一条一条传消息 | Message Queue |
| 做同步、互斥、资源计数 | Semaphore |
| 本机或跨主机通信 | Socket |

## 14. 常用 Linux IPC 排查命令

查看 System V IPC 对象：

```bash
ipcs
```

查看共享内存：

```bash

```

查看消息队列：

```bash
ipcs -q
```

查看信号量：

```bash
ipcs -s
```

```bash

```

```bash

```

```bash

```

```bash
ps -ef
ps -T -p <pid>
top -H
```

## 15. 总结

这部分可以直接压缩成下面这张知识图：

```text
进程 vs 线程
    ↓
进程地址空间隔离
    ↓
需要 IPC
    ↓
Pipe      -> 父子进程字节流
FIFO      -> 有名字的管道
Signal    -> 异步通知
SharedMem -> 共享同一物理内存
MsgQueue  -> 一条一条消息
Semaphore -> 同步 / 资源计数
Socket    -> 本机或跨主机
```

面试中如果被问到“Linux 进程间通信有哪些方式”，可以直接回答：

> Linux 常见的 IPC 包括匿名管道、命名管道、信号、共享内存、消息队列、信号量和 Socket。Pipe 适合父子进程，FIFO 可以用于无亲缘关系进程；共享内存传大块数据效率高，但通常需要配合信号量或互斥锁同步；信号主要做异步通知，消息队列保留消息边界，Socket 则既可以本机通信，也可以跨主机通信。
